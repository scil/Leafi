- Reviewer: codex CLI 0.155.0, `gpt-6-astra`, effort `high`, read-only sandbox, one round (AGENTS.md: one reviewer for an increment round).
- Prompt: [`prompts/adr-0019-wal-round-2.md`](prompts/adr-0019-wal-round-2.md), on the diff of the revision that added the version gate and the replaced `sqlite3.dll`.
- Result: 1 High, 5 Medium, 1 Low. All answered in the ADR and the code before commit; no further round.

| # | Sev | Finding | Answer |
|---|---|---|---|
| 1 | High | The gate sees one process; a fixed opener can switch the file to WAL under a still-running process with the old DLL mapped (a), and the unfixed-library fallback "warn and continue" kept using a WAL file it could not leave (b). | (b) the open now refuses with `UnsafeSQLite` (test). (a) cannot be detected in-process; §1 states it, §2 makes "stop every running Leafi process before any opens `leafi.db` with this code" a step of the procedure. On 2026-10-22 the supervisor (PID 32488) still had 3.49.1 mapped. |
| 2 | Medium | "Cleared at the next checkpoint" is false: a busy `TRUNCATE` does not complete, and automatic passive checkpoints never truncate. | `checkpoint()` returns False when blocked; `forget` says so; the supervisor retries every `CHECKS_EVERY_S` on its own connection off the event loop (test: pinned reader, False, release, retry, empty `-wal`). |
| 3 | Medium | Remnants deleted before `secure_delete`, and backups, keep forgotten content. | Rollout runs `VACUUM` once; `backup` uses `VACUUM INTO`; `forget` lists older backups and tells the owner to delete them (test). Outside the diff: `forget_session` deliberately keeps correction text, encounters and summaries (ADR-0010 §9) — reported, unchanged. |
| 4 | Medium | `journal_size_limit` is not a cap; growth behind a pinned reader. | §4 reworded; reader lifetimes stated; the periodic checkpoint's warning surfaces a stuck reader. |
| 5 | Medium | Catch only contention errors; the 250 ms ADR-0017 §7.3 timeout vs 5000 ms. | Only `SQLITE_BUSY` / `SQLITE_LOCKED` are caught, others raise. §3: 250 ms is not code yet and sets its own timeout when it lands. |
| 6 | Medium | Close only in existing `finally` blocks misses setup failures. | The runner's `finally` now spans everything after the open; checkpoint failure is logged and never masks the result. Supervisor setup failures exit the process, which loses nothing committed (stated in §6). |
| 7 | Low | Read-only openers need `-wal` and `-shm` readable; ordering with ADR-0018's `.users` lock. | §9 corrected; `migrate --learner` opens its Store after taking the lock. |

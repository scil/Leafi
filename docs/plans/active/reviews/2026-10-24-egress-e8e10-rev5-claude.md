## Findings

**1. Medium — X1: "`play()` deletes its `.cam.*` once playback ends (after `stop()` or the drain)" has no correct reading as written.** `play()` returns at HTTP accepted + head pad + clip duration (`go2rtc_camera.py:129`). At that point ffmpeg is still reading the 0.6 s tail in real time, and the file is still open. The drain is not waited inside `play()`: `ListeningGate.speak` waits it (`hub.py:323`), and only after `hub.say` has released its lock. Each implementation the sentence allows fails:
- **Delete when `play()` returns.** Windows refuses the delete (WinError 32, probed). Retrying "after a short wait" inside `play()` holds the Hub lock. If `stop()`'s DELETE failed (`_stop_mouth` gives up after 2 s), ffmpeg plays the rest of the clip, the retry also fails, and the copy stays until the next construction.
- **Wait `drain_s` inside `play()`, then delete.** Every line holds the Hub lock 0.6 s longer, and the gate then waits the returned drain again, so listening reopens about 0.6 s later per line. `test_play_pads…`'s assertion on `sleeps` changes too.
- **Retry in a background task.** Inputs: `activities.py:426` and `:432` say the same word twice in a row (`slow=True`), so both plays share one cache key and one name, `<key>.cam.wav`. The second `prepare` finds the file and skips the padding (`:85`). The first play's delayed delete then removes it before go2rtc opens it. Outcome: the second word is silent (go2rtc 500, or ffmpeg fails to open).

Fix: give every play its own name, for example `<key>.<seq>.cam.wav`, so no two plays ever share a file. At the end of `play()`, try one unlink with no wait. At each `prepare`, delete every other `*.cam.*` in `local_dir`. With that, `camera/` holds at most the clip being played plus a held-open leftover until the next play or session start. That is the same bound the cache sweep already states ("at most until the next session start"). Say so in E9 instead of "at most the clip being played".

**2. Low — X1: the stale clear "at Mouth construction" runs in every process that builds the Hub.** `leafi devices` builds the Hub (`cli.py:27`). Inputs: the owner runs `leafi devices` while a session is between `prepare` and go2rtc opening the file. Outcome: the clip is deleted, and that line is silent. Also, `tests/test_go2rtc_camera.py:104` builds a `Go2rtcCamera` with the default `local_dir`, which is relative to the working directory (`cache/tts/camera`). So the suite would delete files in the owner's real `cache/`. Fix: an explicit `clear_stale()` that `run_session` calls after taking the speech lease, beside the cache sweep. Not in `__init__`.

**3. Low — X3: "every guest with no live session" is undefined, and a list built from rows misses folders.**
- Inputs (a): `forget` builds its guest list while a new session sits between `new_guest` (`loop.py:268`) and its session insert (`:271`). The new guest has no session, so it is on the list. The greeting is synthesised into `learners/G/`, then `forget`'s rmtree runs. Outcome: the clip disappears before playback (the Mouth fails and the line is silent). On Windows, rmtree can instead raise `PermissionError` out of `forget`.
- Inputs (b): a visitor answers no to "Ada?" and yes to "Ben?". `adopt_session` deletes the guest row (`learner_store.py:148`), but `learners/G/` with the "Ada?" clip stays. A `forget` of Ada iterates guest rows, so it never reaches that folder.

Fix: `forget` applies the session-start sweep over the folders themselves. A `learners/<id>/` folder goes when the id has no row, the learner is forgetting, or it is a guest with at least one session and none with `post_done_at IS NULL` (`guests.sweep`'s own condition). A cache delete that fails is logged and does not raise, since the next sweep removes the leftover.

**4. Low — X4: the `EXISTS` on the `'sent'` UPDATE checks before the await, not after.** Inputs: M's `deliver` sets N's row to `'sent'`. During `find_notes`, `createDeck` or `addNote` (`anki.py:150–164`), `forget` marks N, gathers the note ids (this row's `anki_note_id` is still NULL) and deletes the outbox row. Then `addNote` returns, and the ack UPDATE (`:167`) matches 0 rows without any error. Outcome: N's card is in N's deck, and the report does not list it. Fix: when the ack UPDATE matches 0 rows, log the note id. If the learner row still exists, also add the id to `forget.anki_notes` through `_remember_notes`, which `forget`'s final transaction reads. Then reword E9's "never pushed" to state this narrower residual.

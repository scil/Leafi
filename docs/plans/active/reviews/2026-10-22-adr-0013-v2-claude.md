Costs are in tenths. "Boundary" means the 5-tenths penalty for each sentence the path enters with fewer than 2 aligned tokens.

**There are two High findings.**

## High

### H1. A word Leafi supplied is withdrawn as soon as the child echoes it (§Running-record conventions, align rule 7, §Practice)

**Rule.** ADR-0017 §6.1 says a supplied token becomes a candidate with `heard = null`, reason `supplied`. v2 restates that a told word is an error. But rule 7 withdraws any candidate a later match reaches.

**Failing scenario.** "The little brown dog walked slowly." The child stops at `dog`. Leafi asks "Want a hint?", the child says yes, and Leafi says "dog". `dog` (index 3) becomes a candidate. The child's next utterance is "dog walked slowly":
- The fast window contains index 3. Entry costs |3 − pcur| ≤ 1, and the three exact matches cost 0.
- Rule 7 then applies: `candidate → settled`, `withdrawn(reread)` (no utterance created the candidate, so `self_corrected` cannot apply).

The one word the child could not read at all never reaches `practise_errors`, and the `self_corrections` and `repetitions` counts are polluted.

**Further gaps:**
- The supplied path is the only way a function word becomes a candidate. That contradicts "Candidates on function words never exist (rule 7)" in §Practice.
- No pseudocode says what happens to `pcur` when a word is supplied.
- No column holds the reason `supplied`. Migration 5 adds only `unsure_reason + unclear` and `cycle_id` to `miscues`.

**Fix.** Make `supplied` a creation reason, stored in a column, on a candidate that alignment never withdraws (only practice or `close_cycle` settles it). Decide whether a supplied function word is a candidate. Put the supply step in the pseudocode.

### H2. A new cycle on the same page starts a page read with no stated starting state (§Definitions "Page read", §Range and page completion, §Cycles)

**Rule.** "A new cycle starts a new page read (attempt + 1)." The main ADR-0017 loop is read_listen(A) → practise_errors → read_listen(A, `rest`). The second read_listen is boundary-chosen, so `close_cycle(next_reading)` runs and a new cycle opens a new page read of A. v2 gives initial cursors and statuses only for the Interrupted-session resume. For this case it says nothing, and `rest` is never tied to `pcur`/`ccur`.

**Failing scenario,** taken literally: the new page read has `pcur = ccur = 0` and every token U. The learner read s1–s3 (tokens 0–29) and now reads s4.
- A 5-word utterance: the fast window is [0, 0 + 8 + 8) = [0, 16), which cannot reach s4. Either the fast pass accepts a substitution-heavy path in s1 (the session-11 defect at every practice boundary), or the page pass enters s4 for 15. Then rule 9 completes s1–s3 with every token R, so `tokens_unread` reports 30 words the child read.
- A slow reader (1–2 words per utterance): the page pass needs a run of 3 (R = 3), so no utterance is ever accepted. The reader stays `off_task` until `skip` or a page turn.

`/back` after the boundary cannot reach the sentences just read either.

**Fix.** State the initial state of a new cycle's page read of a page already read in this session. For example: the Interrupted-resume rule (`ccur = pcur =` the previous page read's `ccur`, tokens before it C), with `rest` resolving from that point.

## Medium

### M1. Rule 4(c) plus substitute < insert lets one content word anchor a long utterance and turn chatter into candidates (rule 4(c), rule 5 off-task, walkthrough (m))

**Rule.** 4(c) needs exactly one matched token near `pcur`. It does not bound `m` or the number of substitutions. And because a substitution (10) is cheaper than an insertion (12), the DP always substitutes onto the tokens to the right rather than inserting.

**Failing scenario.** Page "Mum went to the shop to buy some milk.", `pcur = 0`, heard "mum can I have a snack after this" (m = 8).
- Path: `mum` exact, then 7 substitutions on `went … some` = 70.
- Inserting all 7 words would cost 84.
- 70 > 5·8 = 40, so the page pass runs. It has no run of 3, so it is not accepted, and rule 2 uses path_f.
- path_f is accepted by 4(c): index 0, content word.

Result: candidates on `went`, `shop`, `buy` (`to`/`the`/`some` are function words); `pcur` jumps to 8. The rule-5 "≥ 3 inserted → `off_task`" observation never fires while page tokens remain to the right. Walkthrough (m) holds only because its chatter has no page word. "Mum", "Dad" and "dog" are in most early readers.

**Fix.** Limit 4(c) to m ≤ 2, or require matched ≥ m − 1 for it. Alternatively, reject any path whose cost per heard word exceeds a ceiling even after the page pass. Today the trigger only searches further; it never rejects.

### M2. Rule 4(c) lets a lone function word anchor, against ADR-0017 §8 (rule 4(c), walkthrough (n))

ADR-0017 §8 requires function words to be "never anchoring alone". v2 4(c) accepts a lone function word at confidence ≥ 0.8, or typed, and walkthrough (n) at 0.9 encodes it. Either amend ADR-0017 §8 or drop the exception. Walkthrough (a)'s typed `The` depends on this exception.

### M3. Slow readers and dropped articles: a lone misreading is lost, and the page pass cannot anchor short or article-dropped speech (rules 3, 4, §Off-task)

**(a) A lone misreading never becomes a candidate.** For a 1-word utterance, a substitution costs 10 + boundary 5 = 15, more than inserting everything (12). Acceptance also needs a matched token. So "dug" for "dog" is `off_task(1)`. The next singleton, "walked", enters at index 4, so `dog` stays U and turns R at completion. The miscue disappears into `tokens_unread` (trace in the appendix). The same error inside "dug walked" does become a candidate. Detection depends on how voice detection splits the utterances.

**(b) The page pass needs a run of 3 (R = 3) adjacent in index.**
- A lost slow reader (1–2 words per utterance) can never be rescued, so the stated replacement for Reposition is not one for this learner.
- The first-words prompt asks for "the first words of your line", and an answer of 2 words is rejected again.
- An ASR that drops "the" breaks every run. In "The dog saw the cat in the park", heard "dog saw cat in park", the longest run is 2, so the lost-start rescue of walkthrough (g) fails for such sentences.

**Fix.** In the page pass, count a run across a deleted function word, or accept two matched content words. Consider letting a single substitution near `pcur` become a candidate when the word's confidence is high.

### M4. Walkthrough (g)'s stated fast-pass cost and acceptance are wrong (§Walkthroughs (g))

The stated path (insert "she smiled", match `at the`, …) costs 55, but it is not the cheapest. The real minimum in the window [0, 17) is **52**: entry at 4 (4), she/the₄, smiled/wood₅, at/lived₆, the/a₇ as 4 substitutions (40), `clever` (0), delete `old` (8), `fox` (0). It matches only 2 of 6 words (< ceil(6/2) = 3) and has no run, so it is **not accepted**. (A 53-cost path, entry 1 with she/the₁, smiled/edge₂, at/of₃, `the`₄ and deletions 14 + 8, is accepted by 4(b) at 3 of 6, but it loses to 52.)

The page pass therefore runs because path_f is not accepted, not because 55 > 30. The outcome is unchanged (page pass 15, s1/s2 R, s3 C, no candidate), but `tests/test_alignment.py` would encode a wrong path and a wrong reason.

The general lesson: at 10 tenths a substitution is so cheap that substitution-heavy paths beat the hand-picked ones. Every walkthrough's "best path" needs a mechanical check, ideally a brute-force oracle in the tests.

### M5. Repeated one-word sentences collapse into a reread of the first (rule 3: boundary and back jump)

**Failing scenario.** Page "Run! Run! Run!" (three sentences, one token each), heard "run run run", `pcur = 0`.
- Straight path: 0 + boundary 3·5 = **15**.
- Repeat path: `run₀`, back jump k = a = 0 (4), `run₀`, back jump (4), `run₀` = 8 + boundary 5 for s1 = **13**. If the boundary counts align operations rather than distinct tokens, it is 8.

13 ≤ 15 (5·m), so no page pass runs. 4(b) accepts it: 3 matched, ≥ 2. s2 and s3 are never reached, and the next sentence's entry turns them R. This is a regression from v1, which had no back jumps.

**Fix.** Penalise only sentences with ≥ 2 tokens and fewer than min(2, len(s)) aligned, and/or forbid k = a.

### M6. Forward entries are cheap and completion of skipped sentences is irreversible, so repetitive texts lose misreadings (rule 3 entry, rule 9)

**Failing scenario.** s1 "I see a red bird." (0–4), s2 "I see a blue cat." (5–9), s3 "I see a red bird." (10–14), `pcur = ccur = 5`. The child misreads s2 as "I see a red bird", a typical prediction error in a patterned book.
- In s2 the path costs 2 substitutions = 20.
- Entering s3 costs |10 − 5| = 5 with 5 exact matches = **5**.

The 5-cost path is accepted by 4(a). s2 completes with every token R and no candidate on `blue`/`cat`, and s3 is credited as read. The page pass's flat 15 entry is just as symmetric (nearest-`pcur` tie-break only). Backward entries are harmless (committed tokens are unchanged); forward ones complete sentences for good. Patterned books are the main early-reader genre.

**Suggestion.** When a forward entry skips a whole sentence, require more evidence, or put off completing the skipped sentence until the next utterance confirms the jump.

### M7. Corrections: stale token indexes, unclear page-read identity, and two rules that disagree (§Correction interaction, §Practice, §Cycles)

- **Stale index.** "The current ReadingState is re-tokenised on r+1" in place, but miscue rows keep their revision-r `expected_token_index`. `close_cycle` writes `tokens[m.expected_token_index].status = settled`. Example: r = "The big cat sat on the mat." with a candidate at `mat` (index 6); the correction deletes "big"; in r+1 `mat` is index 5. `close_cycle` then settles index 6, which is out of range or the wrong token. v1 code carries `Tok.miscue_id`; v2 should locate tokens by miscue id or through the edit map, never by the stored index.
- **Page-read identity.** A page read is "one pass … at one revision", yet the state is re-tokenised to r+1. Say whether the page read keeps its row (with `page_revision_id` updated) or a new one starts. "At most one per (cycle, page, revision)" depends on it.
- **Correction of a page that is not current.** A parent fixes page A from the console while the child is on C. Applied literally, the rule re-tokenises C's state with A's edit map. A's page read is not re-tokenised, so returning to A in the same cycle finds no page read for (A, r+1). A new one starts, with the starting state H2 leaves undefined.
- **Contradiction.** Practice says "a candidate whose revision was corrected is no longer open". Correction interaction invalidates only candidates whose span overlaps the edit, and only those leave the open set. A non-overlapping candidate on a corrected revision is open by one rule and not by the other. This also covers the prompt's case of `/back` plus a correction while a candidate of the same cycle sits on another page: `/back` is correctly page-local, and the correction rule is not.

### M8. Number collapsing ignores the page and leaves the canonical form unstated (§`norm()` v2)

- **The page is ignored.** A page that spells a number as separate tokens breaks. Page "twenty one cats" (tokens `twenty`, `one`), heard "twenty one cats": collapsed to `twentyone`. Against `twenty` that is sim 12/15 = 0.80 and not a word, so `fuzzy` (3); `one` is deleted (8). The result is a false candidate on `one`, which the child read correctly. The same happens for a numeral next to a number word ("page 20 one day …", or "2 two" when the heard run parses, e.g. "twenty two" for "20 two").
- **"and" and commas.** num2words gives "one hundred and five" and "one thousand, nine hundred and ninety". v1 `norm("105")` = `onehundredfive`. Heard "one hundred and five" becomes `onehundred` + `and` + `five` if "and" is not a number word. That is sim 0.74 against `onehundredandfive`: a substitution and a candidate.
- **Retries.** A retry passes only on `exact`/`phones`, so a correct "one hundred five" fails practice.
- **Segmentation.** When the whole run does not parse ("one one two two"), the split is unstated.

**Fix.** Collapse the heard run only when it equals a reading of the expected token at that position (let the DP choose collapsed or uncollapsed), and define one canonical reading form (drop "and" and commas) on both sides.

### M9. The DP is under-specified enough to change the path, and the 100 ms bound is plausible only with a vectorised DP (rule 3, performance claim)

**Ambiguities that change the result:**
- Does the boundary count distinct tokens or align operations, and what happens when a back jump re-enters a sentence (M5 differs by 13 vs 8)?
- Does a sentence crossed only by deletions count as "entered"? v1 code charges it.
- Can a back jump follow an insertion or a deletion?
- In the fast pass, a back jump into the previous sentence needs that sentence's aligned count, which is not in a Markov state.

**State and timing at n = 400, m = 25:**
- About 401 × 26 × 3 (count) × 2 (affine open or extend) ≈ 62.6k states.
- About 13 transitions each (align, deletion, insertion, plus a back-jump fan-out of about 10): ≈ 0.8M, plus the fast pass ≈ 0.2M, plus 10k page entries.
- At v1's style (dict, list building and sort per state, about 4 µs per transition) that is about 4 s. A tight CPython loop is about 0.5 s.
- Only numpy-style vectorisation (affine deletion as cumulative minimum, back jump as per-sentence prefix minimum, tie keys packed into integers) gets to about 5 ms. That must still reproduce the lexicographic tie-break exactly.
- `WordInfo.phones` on 25 new heard words through espeak-ng can alone exceed 100 ms unless phones are computed before `align`. Say whether the timed call includes them.
- The page pass for m < 3 can never be accepted (R = 3), so skip it.

## Low

- **L1. A self-correction inside one utterance is recorded as `reread` (rule 7).** "the little cap sat cat sat" for "The little cat sat": substitution cap/cat (10) + back jump 3→2 (5) = 15 < inserting "cap sat" (24). `cat` becomes a candidate and is withdrawn in the same utterance as `reread`, because "immediately after" excludes the same utterance. `self_corrections` undercounts. The same holds for the self-correction mark when a back jump follows a substitution.
- **L2. The inflection test strips suffixes with no length or lemma guard.** It pairs real misreadings: his/hid (hi = hi), bees/bed (be = be), being/bed, has/had, seed/see, bring/bred. With `observe` these are never candidates (misses, not false alarms).
- **L3. Homographs.** espeak gives one pronunciation per spelling. "she read a book", correctly read /red/ and transcribed "red", is a `substitute`, so a false candidate (also wind, live, lead, tear).
- **L4. Migration 5 gaps.**
  - The `supplied` reason (H1) is missing.
  - The `practices` row outcome for an idle attempt is missing: §Practice step 5 lists {matched, disagreed, unclear, skipped}, yet step 4 produces `idle`.
  - The first-words prompt state is missing: words in the current off-task stretch and an "already prompted" flag. Only `off_task_run` is listed, so "≥ 6 heard words … once per stretch" lives in prose only.
  - The `FUNCTION_WORDS`, word-list and `phones_version` that produced an observation's category are not stored, so the eval replay cannot be reproduced.
  - `observations.category` is single-valued, yet `function_word` overlaps `substitute`/`inflection`, and a deletion has no pair class.
  - The `created_by` utterance sequence (needed by rule 7) and the per-token `miscue_id` are not in the v2 `ReadingState` definition.
- **L5. `off_task_words` is computed "from the observations".** A rule-4 rejection returns `observations = []` and only an event, so whole off-task utterances are not counted. Words genuinely read before a mid-utterance jump back are counted as off-task (appendix, back three sentences).
- **L6. Rules stated twice, or stated differently.**
  - `pcur` is defined twice: the Definitions' "first token not P/C/M/S after the last aligned token" vs rule 7's `max(pcur, last + 1)`.
  - Bold "nothing is said at a sentence end" vs ADR-0017 §6.1's `sentence_end` mode (an encourage line after a self-correction).
  - "Candidates on function words never exist" vs `supplied` (H1).
  - Practice vs Correction interaction on open candidates (M7).
- **L7. Losses from "no miscue row" for function words and inflections.**
  - The false-alarm evaluation loses nothing: content words only, and observations keep the category.
  - Difficulties can never see a systematic dropped "-ed" by an L2 learner. If Migration 5's new `knowledge_items` kind `pattern` is meant to carry that, v2 defines no source for it.
  - Function-word deletions and inflections end `committed`, inflating `tokens_committed`.
  - A dropped sentence-initial "The" (free gap before entry) ends R, inflating `tokens_unread`.
- **L8. Practice step 4:** the result of a `fail` on retry 1 followed by no reply on retry 2 (`disagreed` or `idle`) is unstated.

**The page-pass trigger and rules 4(a)–(c), as asked:**
- **Wrong page-wide paths.** The 0.5-per-word trigger is reasonably safe against accepting a wrong page-wide path. A wrong page path must beat path_f outright, which needs repeated text. The wrong accepts come from the fast pass instead (M6) and from the trigger never rejecting (M1).
- **Right paths rejected.** These come from R = 3 adjacency in index (M3b) and from requiring a match for singletons (M3a).

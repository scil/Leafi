1. **High — Anki decks are neither isolated nor stable.** [anki.py:37](E:/GitHub/scil/Leafi/leafi/study/anki.py:37)  
   Two learners named Alex both get `Leafi::Alex`; forgetting either with `--delete-anki-deck` deletes their shared deck. Renaming a learner changes the computed deck without moving existing cards. Additionally, the migrated learner keeps `Leafi`, while new learners receive its subdecks: querying `"deck:Leafi"` includes those learners’ cards, which `due_cards` still returns with `knowledge_item_id=None`. [Anki documents that deck searches include subdecks.](https://docs.ankiweb.net/searching.html#tags-decks-cards-and-notes)  
   The Decision log’s naming choice therefore contradicts ADR-0018’s “each learner’s own deck.” Persist a unique, stable deck assignment and prevent overlapping ownership.

5. **Medium — Garbage collection can release the process lock before closing SQLite.** [storage.py:470](E:/GitHub/scil/Leafi/leafi/core/storage.py:470)  
   An unclosed Store has no finalizer tying connection closure to lock release. Dropping it destroys `_FileLock` and its file handle, but CPython’s SQLite connection can survive in an internal reference cycle until cyclic GC. I confirmed the connection remained usable after its Store and lock owner were destroyed. An exclusive migration can consequently acquire `.users` while that connection remains open. Finalization must close SQLite before releasing the lock.

## 2. New defects introduced by the fixes

### D1 (verified, P1 for voice mode): a timed-out `listen()` leaves a finished main task that answers the next `listen()` with an instant `None`

`leafi/study/session.py:187-198` (`listen`). `_main_task` is created with `listener.next_utterance(timeout_s)` and `asyncio.wait(..., timeout=timeout_s)` runs a second timer on the same duration. The `wait` timer is armed first, so it fires first; `listen()` returns `None` but keeps the task, which completes with `None` one tick later and is handed back verbatim by the next `listen()` call whatever its timeout. In voice READ every pause therefore yields two `None`s (idle accrues at double rate), and worse, the state entered because of the pause gets its first input as an immediate timeout.

Repro (script `repro_review2.py`, cases B and C, voice `ScriptedListener` subclass whose `next_utterance(t)` sleeps exactly `t` then returns `None`, like `VoiceListener`'s own deadline):
- B: page "The dog ran far.", say "The dog red", pause → PRACTICE. `listen(practice_retry_s=5)` never reaches the listener (timeouts seen: `[0.1, 0.1, 0.1, 180, …]`); result `{'ran': ('unsure', 'idle')}` instead of waiting for the retry "ran" → `withdrawn(practice)`. Leafi says "Let's try ran together … We'll leave that one for later" in one breath.
- C: "The dog ran", pause → CHECK. The first question is graded with `u=None` → `unavailable`, the answer is read out at once; the learner's answer then lands in the after-check loop as a no-op. `answers stored: []`.

Failing-test sketch: `tests/test_control_dispatch.py` with `SlowVoice([_voice("The dog red"), 0.1, _voice("ran"), "/stop"])`, `settings.sentence_pause_s = 0.1`, `practice_retry_s = 5`: assert miscues `== {"ran": ("withdrawn", "practice")}` and `listener.timeouts` contains `5.0`.

Fix: let `listen()` own the deadline — create `_main_task` with `next_utterance(None)` and keep only the `asyncio.wait` timeout (a pending task then simply carries over, which is the stated intent "nothing is cancelled, nothing is lost"); or, on a `wait` timeout, cancel-and-clear a main task that was created with a finite timeout. Text mode is unaffected (every `None` there goes straight to WRAP), so this does not block the text-mode session, but it must be fixed before the first voice session.

### D2 (verified): `test_cloud_tts_receives_only_redacted_leafi_lines` is vacuous — and shows that a text-mode listener with a Mouth is drained during playback

`tests/test_privacy.py:172-207`; cause in `leafi/study/session.py:133-145,150-157` (`say`, `_control_read`). When `control_source is self.listener` (text mode with `voice_policy != none`), `say()` reads the *main* listener while a line plays; a `ScriptedListener` answers immediately, so the whole script is consumed into `_inbox` during "hello", and the `/stop` that ends every script is inserted at index 0. The explain and the `/fix` the test is about never run (repro A: edge received only the hello line; transitions `FIND_PAGE, REVIEW_DUE, READ, WRAP`). For a real console the behaviour is defensible (lines typed during speech queue up), but the test's assertion `assert spoken` cannot distinguish "redacted" from "never spoken".

Fix: in the test, give the Mouth a real duration and feed lines through a `control_source`/listener that waits for `listen()` (e.g. a queue-backed console that only yields after each `Display("listening")`), then assert the explain line and the two correction lines were actually synthesised (edge gets the redacted explain line; the correction lines reach the local backend). Also add an assertion on `EXPLAIN`/`CORRECT` in `s.flags.transitions`.

### D3 (possible): `/skip` typed during playback is swallowed when the line is still being synthesised

`leafi/study/session.py:171-172`, `leafi/core/hub.py:274-279`. `_during_playback` calls `hub.skip_current()`, which only stops Mouths in `_playing`; between `say()` starting the speak task and `Hub.say` reaching the play phase (TTS synthesis, cloud edge-tts round trip) `_playing` is empty, so the `/skip` does nothing and is not queued either. A `/stop` in the same window is safe (generation bump is checked after synthesis). Fix: when nothing is playing, bump a "skip the next clip" flag checked after synthesis, or queue the control.

### D4 (possible, design gap vs. security.md red line 5): `/skip` during playback never reaches the state

`leafi/study/session.py:125-126, 171-172`. A `/skip` typed while Leafi models a practice word cuts the audio but is not delivered to `_practise_word`; the learner must type it again once listening resumes. ADR-0013 only promises `/stop` during playback, so this is a documented choice rather than a bug, but "skip works in every state" is weaker than stated.

### D5 (possible): session cancellation orphans the speak task

`leafi/study/session.py:136-145`. If `run()` is cancelled (Ctrl-C through `asyncio.run`) while `say()` is inside `asyncio.wait({speak, ctl_task})`, `speak` is not cancelled: it keeps the gate lock and plays the clip to the end while `run()`'s `finally` releases the lease. `_cancel_inputs` cancels only the input tasks. Fix: `try/except CancelledError: speak.cancel(); await speak` around the wait loop (the Hub side is now cancellation-safe, #6).

### D6 (possible, minor): an Eye page turn during REVIEW_DUE becomes a no-op loop

`leafi/study/session.py:192-195, 211-227, 464-481`. `_page_open` is already true during REVIEW_DUE; the page event surfaces as `/page`, the review loop answers "That doesn't do anything right now", the watcher restarts, `tracker.last` is still the old frame, so it fires again on the next poll — a no-op line every `page_poll_s` until the review ends; the turn is then handled in READ. Fix: route page/stop uniformly in `review_due` (via `_turn_page`) or keep `_page_open` false until READ.

### Checked and found sound
- ListeningGate / Hub: no deadlock (gate lock → hub lock only; `stop_speaking`/`skip_current` lock-free), no double settlement (`_depart` then `wrap` → `_end_page_read` uses `COALESCE(ended_at, ?)`; `open_for_read` empty on the second pass), no lost control in `listen()` (undrained `done` tasks stay in `_main_task/_control_task` for the next call; console wins ties). The generation check in `Hub.say` relies on the speak task capturing `generation` before `_during_playback` runs; it does today because `create_task` schedules the first step before `asyncio.wait`'s done-callback and neither `pause()` implementation yields — fragile, but correct.
- Stable miscue ids: every state transform deep-copies; `retokenize` keeps ids for untouched tokens and the correction invalidates exactly the touched ones; `_miscue_at` re-checks the row is still `candidate`.
- Edit map: `map_point` affinity verified for insertion, deletion, replacement, multi-edit maps and cursor mapping with the `first_touched` clamp.
- Transactions: `Store.transaction()` nesting is depth-counted and rolls back on any `BaseException`; `set_status`/`add_encounter`/`upsert_item`/`reconcile` compose correctly inside `apply_correction`, `close_stale_sessions` and `_persist`.
- Cosmetic: `session.py:58` carries a stray comment ("# scorer threshold …") that belongs to line 57; `_control(self, u, *, reading)` keeps a dead parameter.

## Decisions

**E1 One rule: cloud-bound text is redacted by content, never refused by its source.** Basis: owner (O1). `prepare`'s pipeline for study purposes becomes: destination allow-list → locality → **redaction** (E2) → media check → write the attempt → transmit. `_gate`, `may_send`, every source refusal ("cloud.text off", "a guest", "parent text", "unknown provenance"), the substitutes and `withheld` counts go. A text is never refused for what it is; it is sent redacted. The only text refusals left: the detector `loading` inside a session (E3) and the version/fingerprint checks of `admit` (E6). Provenance: *adapted* from content-redaction middleware at one seam before the model call (LangChain `PIIMiddleware` S3, LLM Guard Anonymize S4, NeMo PII rails S5); Leafi keeps its own lists and surrogates instead of their detectors (R§5).

**E2 What is redacted where.** Basis: owner (O5); reference (S5's per-field scope).
- **Lists** apply to every text of every request, book text included (as today: a household name in a book is replaced too).
- **The detector** (Presidio PERSON / ORGANIZATION / LOCATION) applies to every text **except book fields**. `leafi.privacy.egress.Text` gains `book: bool = False`; the request builders set it on the page text, the sentences, the expected words and book titles (`observe.page`, `kinds.*_sections`, `generate.learner_context`'s page part, `prompts`' page helpers); every other `Text` is scanned. **Plain strings** (a caller's constants: the system text, the schema, the model id, roles) get the lists only, as today: a detector replacement inside a model id or a schema value would break the request, and the M5 rule already makes every person- or book-derived text a `Text` (implementation note, commit 1). `Text(value, provenance, sources)`'s old constructor is kept for one release as a shim that maps `provenance == "page"` to `book=True` and ignores the rest, so edge-tts and every M5 caller keep working until E10's commit converts them.
- A detected entity not on the lists becomes a surrogate like a listed one and is mapped back in the reply (ADR-0018 §3, unchanged).
- Provenance: lists and map-back *adopted* from ADR-0018 §3 (reversible placeholders as S4's Vault, S6's numbered placeholders); the book flag *original* (searched: S3–S6 scope by message role, not by field; Leafi's requests mix book and other text in one message, so the scope is per `Text`).

**E3 Detector states.** Basis: owner (O6, ADR-0018's 2026-10-23 decision); project constraint (M7 D8).
- `privacy.name_detector = off`, or the model missing: lists only; `leafi doctor` keeps reporting it; an unanswered school, a friend's name or a lower-case name then leaves verbatim (O6, stated in ADR-0021).
- `loading` or `unloaded` inside a session: non-book text for a cloud destination is refused with `detector not ready` (M7 D8 today, widened from learner leaves to non-book text), so the call falls back; outside a session `prepare` waits, as today.
- Provenance: *adopted* from M7 D8's detector state machine.

**E4 Settings removed.** Basis: owner (O2); project constraint (the inventory, group E).
- Learner key `cloud.text`: removed from `privacy/settings.KEYS`; a stored value is ignored on read and the writer refuses the key; `LearnerPrivacy.cloud_text` and `cloud_text_allowed` go; `consents` rows with purpose `cloud_text` stay as history, none is written (the CHECK keeps the value).
- Household `.env` keys `CLOUD_PARENT_TEXT` and `PRIVACY_TTS_LEARNER_LINES`: removed from `config/env-schema.json`, `.env.example`, `envprotect.PRIVACY_FLOOR`, `versions.POLICY_KEYS` and `core/config.py`; an existing value in `.env` is ignored and `leafi doctor` names it as obsolete. Removing a key from `POLICY_KEYS` changes the policy fingerprint once, so a running process refuses study text until restarted (M5d behaviour); the rollout restarts every Leafi process (E11).
- Provenance: *original* (a removal).

**E5 Guests and unconfirmed sessions.** Basis: owner (O3). Text from a guest or a session not yet confirmed by `identify` is redacted and sent like an enrolled learner's. Unchanged for guests: no media consent, no export, no post-session notes, the guest end states and sweep (ADR-0018 §1). Identification prompts keep their local TTS by E7 (they contain names). Provenance: *original* (a removal).

**E6 The provenance type and its propagation go.** Basis: owner (O1, O4); project constraint (inventory groups B, C).
- Removed: `leafi/core/provenance.py` (`Provenance`, `PARENT_SOURCE`, `join`, `of_output`, `SYSTEM`, `Leaf.prov`, `Leaf.substitute`), `Turn.provenance`, `Synthesizer.synth(provenance=)`, `Content.provenance`, `Result.provenance`, `content_provenance`, `explanation_provenance`, `render.filter_turns` and `AssistantTurnWithheld`, `call._withheld`.
- `Leaf` becomes `(value, book: bool)`; `Turn` keeps `role` and `sections`.
- `Brain.eligible`: `answer` and `judge` may use any configured backend (`CallContext.may_use_cloud_text` goes).
- `versions.snapshot` keeps a version check for the **request's learner** (school and media settings, household terms) instead of per source learner.
- The parent notification always names the learner by surrogate (the lists replace the real name anyway).
- Provenance: *original* (a removal).

**E7 Text-to-speech by content.** Basis: owner (O1); reference (M5 D13's protected-name rule). A line is synthesised by Kokoro when its text contains a listed protected name **or a detector entity** (the line scanned as non-book text); otherwise by the configured backend (edge-tts by default) through `prepare`. So a child never hears a surrogate name. The cache sidecar drops `provenance_class` / `source_learners`; clips are cached per owning learner and `forget --learner` deletes that learner's folder, as E9 says (U9, W1–W3). Provenance: *adapted* from M5 D13 (the class half dropped, the detector added).

**E8 Migration 7: drop the provenance columns, with the runner as it is (U1–U3).** Basis: owner (O4); project constraint (`storage.migrate_file`, `_step`); reference (S2).
- **Freeze before editing (U1).** `SCHEMA_V6 = <today's SCHEMA>` is frozen beside `SCHEMA_V5`; step 6 targets `SCHEMA_V6` (today it targets the live `SCHEMA`, `storage.py:822`, so editing `SCHEMA` would rebuild a v5 file straight into the v7 shape, stamp it 6 and strand it). Then `SCHEMA` loses the 20 columns (`activities.{outcome,assessment}_*`, `brain_calls.{payload,response}_*`, `utterances.*`, `encounters.{context,explanation}_*`, `learner_notes.*`, `book_notes.*`, `anki_outbox.card_*`); `_PROV` stays, used only by the frozen `SCHEMA_V5` / `SCHEMA_V6` (deleting it makes importing `storage.py` raise `NameError`, V1); `_V5_COPY` stays; `SCHEMA_VERSION = 7`. In `migrate_file` the `version == 5` branch now sets `version = 6` after its step (today it does not, V1), so a file at 4 or 5 continues into step 7.
- **One mechanism (U2).** `migrate_file` gains `if version == 6: _step(conn, 7, SCHEMA, {}, result, _hook)`: `_step` already rebuilds every table whose DDL differs from the target, copying the shared columns, in one transaction, under the exclusive `.users` lock that excludes every `Store` (ADR-0019 §5's protection is this lock; there is no separate `migrate()` `BEGIN IMMEDIATE`). The research's DROP COLUMN finding (S2: legal on all 20 columns, confirmed by all three reviewers) stays a recorded fact, not a second mechanism. A file at 4 or 5 runs its earlier steps first, as today.
- **Cleanup after the commit (U3).** `migrate_file`'s connection sets `PRAGMA secure_delete = ON` (it is a raw connection; `Store` sets it per connection). After the last step commits, still holding the lock: `VACUUM`, then `PRAGMA wal_checkpoint(TRUNCATE)`; a failure there is reported and leaves a valid version-7 file. `leafi migrate` on a file already at the latest version runs the same cleanup again (idempotent), so a crash between the commit and the cleanup is completed by rerunning the command: `migrate_file`'s early return for `version == SCHEMA_VERSION` becomes "take the lock, run the cleanup, return", and the CLI's "already at schema N" branch prints whether the cleanup completed. Completion means the checkpoint reported not busy (the existing `_truncate` helper's busy flag), not merely that no exception was raised. The cleanup always runs under the exclusive `.users` lock, so an open `Store` anywhere makes the command refuse, as for a migration (V1).
- **Rollout (U2).** `Store` refuses a version-6 file (`NeedsMigration`); the owner runs `python -m leafi migrate` with every Leafi process stopped. It takes its own `leafi-v6-<stamp>.db` backup (no extra manual backup). Restoring that backup gives a version-6 file that needs `leafi migrate` again, and any backup older than a `forget` brings the forgotten learner back (ADR-0019 §8); the rollout and `leafi forget`'s backup notice say both (U10).
- **Numbering (U12).** M7's planned `item_status_events` migration becomes 8 and M7f's interests migration 9 (neither is written); both designs carry the note.
- `tests/test_migration_7.py`: files at 4, 5 and 6 with rows in every table migrate to 7; `schema_of(migrated) == schema_of(fresh)` (as tests 5 and 6 do); none of the 20 columns remains; every row and index survives; `integrity_check` and `foreign_key_check` clean; the failure-injection hook mid-step 7 leaves the file at 6 and a rerun completes; a canary `'[987654321]'` in a `*_source_learners` column (a value no other column holds) is absent from `leafi.db` and `-wal` after the cleanup; a cleanup cut off after the commit is completed by a second `leafi migrate`. `test_migration_6` now migrates to `SCHEMA_V6` and asserts version 6 at that step, not `SCHEMA_VERSION`.
- Provenance: *adopted* from Leafi's migration runner (`_step`, the `.users` lock, the auto-backup; migrations 5 and 6) and SQLite's `VACUUM` / `wal_checkpoint` (ADR-0019 §6–§7); the frozen-schema pattern *adopted* from `SCHEMA_V5`.

**E9 `forget` and the write fence by owning learner (U5–U9, U11).** Basis: owner (O4, U6); project constraint (`learner_store`, `records`, `call`).
- **Owner sets.** `learner_store.DIRECT_OWNED` (today's `DIRECT`, owner in `learner_id`) and `SESSION_OWNED = {activities, utterances, brain_calls}` (owner = `reading_sessions.learner_id` of the row's `session_id`): the same session-owned tables today's provenance registry fences, now listed explicitly instead of derived from columns (U5). **Why the other session tables are not fenced (V8, W5):** `cycles`, `page_reads`, `observations`, `miscues` and `practices` do hold learner text (`miscues.heard`, `observations.heard_text`, read into Brain requests). They have exactly two writers: (a) the live session, which cannot race N's forget because `forget --learner N` refuses while N owns a session with `post_done_at IS NULL` (`LearnerBusy`), and (b) startup recovery (`rows.recover`), which selects sessions by `ended_at IS NULL` and so also reaches a session whose finalisation failed after `post_done_at` was set (`loop.run_session`). **Recovery therefore checks the owner itself (X2):** recovery has two per-session loops — `rows.recover` (activities, cycles) and `records.close_stale_sessions` (miscues `settle_open`, `page_reads.reading_state`, `reading_sessions.ended_at` / `summary`, `recompute_difficulties`) — and both open each session's transaction (`Store.transaction()`, already `BEGIN IMMEDIATE`, so `forget`'s marking `UPDATE learners SET forgetting=1` cannot commit in between) with a **standalone first statement** `SELECT 1 FROM reading_sessions rs JOIN learners l ON l.id = rs.learner_id WHERE rs.id = ? AND l.forgetting = 0`; no row → the session is skipped with no write (rev 4 hung the check on the first UPDATE, which matches nothing in the failed-finalisation state and would have skipped healthy sessions too). Each loop also catches `LearnerUnavailable` from the fenced writes it makes (difficulty recomputation) per session: the session is skipped and logged, never aborting startup. The final bulk `UPDATE reading_sessions SET post_done_at = …` touches only a maintenance column (X5). `forget` deletes such a session with the rest of N's. A later session of N cannot exist while N is being forgotten (`identify` never offers and `adopt` never adopts a forgetting learner, ADR-0018 §1). Tests: the failed-finalisation state (`post_done_at` set, `ended_at` NULL, no running activity) recovered normally by both loops; the same state with the learner marked forgetting skipped by both loops without a write and without aborting startup; `LearnerBusy` still refusing a live session. `egress_log` is keyed on `learner_id` and stays a plain insert, swept by the final by-owner delete (U11).
- **The fence, in the statement (U5).** `insert` (direct): `INSERT … SELECT … WHERE EXISTS(SELECT 1 FROM learners WHERE id = :learner_id AND forgetting = 0)`. `insert_named` (session-owned): `INSERT INTO activities(…) SELECT … WHERE EXISTS(SELECT 1 FROM reading_sessions rs JOIN learners l ON l.id = rs.learner_id WHERE rs.id = :session_id AND l.forgetting = 0)`, so a missing session or learner refuses (`LearnerUnavailable`) instead of raising a foreign-key error. `update_named`: `UPDATE activities SET outcome = :v WHERE id = :id AND EXISTS(SELECT 1 FROM reading_sessions rs JOIN learners l ON l.id = rs.learner_id WHERE rs.id = activities.session_id AND l.forgetting = 0)` (no separate owner read); zero rows → `LearnerUnavailable`. Codex probed both on SQLite: N forgetting → 0 rows; N's session deleted → 0 rows; M → 1 row. The `sources=` argument and `stated_sources` go.
- **What the architecture test fences (V3, W4).** Every INSERT into a table of `DIRECT_OWNED | SESSION_OWNED`, and every UPDATE of those tables **except** assignments to a named maintenance list. The list is inverted on purpose: a column list of text fields went incomplete twice (rev 3 missed `encounters.example`, `utterances.words`, `book_notes.topic` / `characters`). `test_architecture` holds `MAINTENANCE_COLUMNS: dict[table, set[column]]`, each entry with a one-line reason, written out here from today's raw UPDATE sites (X5):
  - `reading_sessions`: `ended_at`, `post_done_at` (incl. the bulk set in `rows.recover`), `book_id`, `summary` (JSON of counts and enum strings by construction, `records.summary`); **not** `learner_id` (only `adopt_session` in `learner_store` and `guests.discard`'s function exemption re-key a session);
  - `activities`: `status`, `ended_at` (incl. the bulk set by session in `rows.recover`), `cycle_id`;
  - `review_answers`: `state`, `sent_at`, `acked_at`; `knowledge_items`: `status`, `updated_at`;
  - `anki_outbox`: `state`, `attempts`, `updated_at`, `anki_note_id`, `card_ids` (ids), `attempted_fields` / `last_acked_fields` (JSON of hashes), `last_error` (an AnkiConnect error string) (X4, Y5).
  The two bulk sites cannot use a per-row `update_named` and need not: they write maintenance columns only. Its scanner parses the `SET` targets of every `UPDATE <owned table> SET …` string in `leafi/`, module- and class-level constants included (today's `ast.walk(fn)` misses module-level SQL): targets are `(\w+)\s*=` at parenthesis depth 0 (so `COALESCE(?, summary)` is not a target), and any `{}` placeholder inside the SET of an owned table is refused, as is any UPDATE whose table name is not a literal, outside `learner_store` (Y5). An assignment to any column outside the table's maintenance set must go through `update_named`. Negative cases: raw UPDATEs of `encounters.example`, `utterances.words`, `book_notes.characters` and `reading_sessions.learner_id` are refused; a raw `UPDATE activities SET status=?` passes.
- **The audit write (U8).** `call._insert` catches `LearnerUnavailable`, logs the refusal (call id, outcome, no text) and drops the row, which `flush_audit` then pops from `pending_audit`; `_withheld` goes with E6. So a late audit row for a forgetting learner never raises into a Brain call or `finalize`.
- **Names (U7, V6).** In the marking transaction, `forget_learner` keeps every **person** name the lists protect for N: `display_name` and `alias`, deduplicated case-insensitively (`Ada` and `ADA` are one term), each inserted as kind `name` with `former_learner_id = N` only `WHERE NOT EXISTS(SELECT 1 FROM household_terms WHERE term = ? COLLATE NOCASE)` (the index `household_terms_term` is unique case-insensitively), so a rerun or an existing term is a no-op. Existing `household_terms` rows are left in place with their kind: a school or other term referenced by N's settings may be shared by a sibling and stays as it is; a person term already present (added by hand) is not reclassified. `pseudonym.load_lists` reads every `household_terms` row whether or not N still exists, so the kept names stay replaced.
- **What `forget --learner N` deletes.** N's direct rows; every row reached through N's sessions, including **every note attached to one of N's sessions (`learner_notes.session_id`), whoever owns it** (`records.py:286`, kept: a note written during N's session is N's session record), and other learners' notes cited only by those sessions' activities (today's citation rule in `_delete_session_records`, kept). A note of M attached to M's own session survives, losing only its citations of N's activities (V7); `data/learners/<N>/`. `records._purge_derived` and its `json_each(source_learners)` rescan go; **the last transaction repeats the by-owner deletes** (direct tables, `egress_log`) before deleting the `learners` row, so a row written between batches does not make the final delete fail (U11).
- **Stores outside the database: the TTS cache per owning learner (U9, W1–W3; the structural move).** Rev 3's purge under the study lease failed three ways: the lease is check-then-write, not exclusive (`lease.acquire`, W1); a cancelled Kokoro executor worker and the habit track (`agent/tts.py`, writing into the same `cache/tts/` without the lease) keep writing after any lock is taken (W2); and the marker's lifecycle and path were undefined (W3). Rev 4 removes the need for a purge that races writers:
  - **Layout (X6).** The study `TtsService` caches into `<settings.cache_dir>/tts/learners/<id>/`, where `<id>` is read from `runtime.attribution.get()` at the start of `synth`, before the backend is awaited: the session sets the attribution to its guest at start and `adopt()` moves it in place (`runtime.attribute`), so clips made before adoption stay under the guest's folder and later ones under the learner's, with no new port method. No attribution (text mode, a CLI path) → `<cache_dir>/tts/shared/` (no writer today). The habit track's root files (`cache/tts/*.mp3`) are never touched by Leafi's study code (O7). Cache hits are looked up only in the owner's folder (a little less sharing; the greeting is re-synthesised per guest).
  - **The camera Mouth's copies become transient (X1, Y1, Y2).** `Go2rtcCamera.prepare` writes a padded `<key>.cam.wav` of every clip into `cache/tts/camera/` and today never deletes it, so a copy of a forgotten learner's line would outlive `forget`. go2rtc's ffmpeg reads the file in real time (`-re`, `tools/go2rtc/PATCHES.md`) and still holds it open when `play()` returns (the 0.6 s tail is drained later by the listening gate), and Windows refuses to delete an open file (WinError 32, probed). So: every play gets its **own** file, `<key>.<seq>.cam.wav` (`seq` a per-process counter), so two plays of the same word in a row (`activities.py` says the practised word twice) never share one; at the end of `play()` one `unlink` is tried **without waiting** (a refusal is ignored); each `prepare` first deletes every other `*.cam.*` in `local_dir`, which by then nothing holds. A separate `clear_stale()` runs once in `run_session` after the speech lease is taken, beside the cache sweep — never in the constructor, because `leafi devices` and the tests build a Mouth too (a test with the default relative `local_dir` would delete the owner's real `cache/tts/camera/`). So `camera/` holds at most the clip being played plus one held-open leftover until the next play or session start — the same bound as the cache sweep. (This file can make the camera speak: plan mode, mocks only — Status.)
  - **Forget.** `forget --learner N` deletes `<cache_dir>/tts/learners/<N>/` after marking N, and again in its last transaction step (with U11's by-owner sweep), and then **applies the sweep over the folders themselves** (X3, Y3): `identify` speaks enrolled names — the console list, "Ada?" — into a guest's folder before adoption, and that folder outlives the guest row when the guest is adopted (`adopt_session` deletes the row) or is kept `unconfirmed`. A `learners/<id>/` folder is deleted when its id has no learner row, the learner is forgetting, or it is a guest with at least one session and none with `post_done_at IS NULL` (`guests.sweep`'s own condition, so a guest whose session is just starting is left alone). A cache delete that fails (a file held open on Windows) is logged and never raises; the next sweep removes the leftover. No other learner's writer uses N's folder, and N's own session has ended (`LearnerBusy`), so no lock is needed. A late file — a cancelled Kokoro worker from N's ended session finishing after the second delete — is caught by the sweep below.
  - **Sweep by owner.** At each session start, before the first synthesis, the study runner deletes every `learners/<id>/` folder whose id is not a learner row or belongs to a learner with `forgetting = 1`, and the guest sweep (ADR-0018 §1) deletes a guest's folder with its rows. So a stray file lives at most until the next session start; `forget`'s report says so.
  - **Anki sync (X4).** `anki.sync_outbox` runs in another learner's `deliver` step, outside `LearnerBusy`'s reach: its query joins `learners` with `forgetting = 0`, and its UPDATE to `'sent'` carries the owner `EXISTS` predicate (0 rows → the row is skipped, no raise). One residual remains (Y4): `forget` can mark the learner and gather note ids while `addNote` is awaited; then the acknowledging UPDATE matches 0 rows. In that case `sync_outbox` logs the returned note id and, while the learner row still exists, adds it to the list `forget` reads in its final transaction (`_remember_notes`), so the card is listed for the household to remove; a card whose learner row is already gone is only logged.

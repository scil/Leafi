# M5 egress and privacy: implementation design

Plan `2026-10-22-ai-led-study.md` → M5. ADR-0018 (accepted) owns the mechanisms: the two seams (call-level `prepare`, transport-level mediation), attempt tokens bound to the body's HMAC, single use, one text retry, synthetic 403; the socket guard with grants, gateway ports and a `lan` class; provenance filter and pseudonymisation (lists + Presidio); TTS routing by provenance; the privacy settings table; the §7.5 documents. This note decides only what the ADR leaves open. Where a decision adds a mechanism, a name or a data shape the ADR does not state, it is marked **[beyond ADR]**.

## Decisions

**D1 Layering [beyond ADR].** New package `leafi/privacy/` (`egress.py`, `destinations.py`, `tokens.py`, `pseudonym.py`, `detector.py`, `secret.py`, `settings.py`, `versions.py`). It imports only `leafi.core`. `leafi/ops`, `leafi/devices`, `leafi/services` and `leafi/study` may import it; `leafi.core` may not. `tests/test_architecture.py` gains the rule; `ops` "imports only core and devices" becomes "core, devices and privacy". ADR-0002 gets a one-line note.

**D2 The socket guard and grants (T7, T8, R7, R8, S8, S30, S31).** `leafi.bootstrap.install()` installs the guard and the environment of D15. It is called first by `leafi/__main__.py`, by every `leafi` module that has a `__main__` block, and by every supported script under `scripts/` that builds Leafi services (`scripts/probes/*`, `scripts/prototypes/*`). `leafi.app.build()` and the service constructors that open network or model clients raise unless bootstrap has run, so a forgotten entry point fails at start rather than running unguarded; the test suite runs bootstrap from `conftest.py` in log-only mode, and a subprocess test asserts the order (guard installed before the first service import). Importing `leafi` or `leafi.core.lease` alone installs nothing and checks nothing, so the habit track (`agent/`) keeps its ADR-0011 behaviour unchanged. The env-read architecture test exempts `leafi/bootstrap.py` only.

The guard patches `socket.socket.connect` / `connect_ex` / `sendto` / `sendmsg`, `socket.create_connection`, `loop.sock_connect`, `loop.create_connection` (including `sock=`), `loop.create_datagram_endpoint` and `loop.getaddrinfo`; a blocking audit hook on `socket.connect`, `socket.sendto` and `socket.getaddrinfo` catches what the patches miss. Proxies are refused: every egress client is built with `trust_env=False`, and `install` clears `HTTP(S)_PROXY` / `ALL_PROXY`.

A grant is an id in a `contextvars.ContextVar` plus an entry in a shared, lock-guarded active set (`Grant(id, host, addresses, port, expires, kind)`); the guard honours the id only while it is in the set, and `egress` removes it in `finally`. Grants are opened inside the mediating transport's `handle_async_request` / `handle_request`, in the thread or task that connects. **A grant lives until its response is finished**: the transport wraps the response stream, and the grant is revoked when the stream is closed, fully read, cancelled, or discarded by a retry (the discarded response is closed first); a streaming download therefore keeps its grant (and its token's expiry does not cut it, D7) until the file is written. **Every socket admitted under a grant is shut down at revocation**: the guard records each socket it lets connect in a per-grant weak set, and membership follows the socket into TLS (`SSLContext.wrap_socket` / `SSLSocket._create` are patched, because wrapping detaches the recorded socket and leaves it at fd −1, U1). Revocation calls only `shutdown(SHUT_RDWR)` on each member still open — safe from any thread, and the owner sees EOF or a reset; closing stays with the owner (an asyncio socket is never closed underneath its transport, U2). This covers the transport's own connection and any socket a child task or library thread opened under a copied grant. A response never closed is revoked at its deadline at the latest (a download's overall deadline, 30 s otherwise). On Windows asyncio the audit hook does not see the Proactor's `ConnectEx`, so the `sock_connect` / `create_connection` patches are the only enforcement there (stated). Egress clients keep no idle connections (`max_keepalive_connections=0`), so no pooled connection outlives its grant to be closed underneath another request. Library-mode edge-tts closes its `ClientSession` at the end of the call, inside the grant. Tests: a child task, and a thread with a TLS socket, that connect under the grant and keep their sockets find them shut down after revocation; a streamed download keeps its grant until the stream closes; cancellation mid-stream revokes.

Connect check, in order: `LEAFI_NO_NETWORK=1` refuses every non-loopback address and every gateway port, grants and `lan` included; a gateway port (`MAGPIE_URL`'s, `OLLAMA_URL`'s port) on any loopback or local-interface address needs a grant; another loopback port passes; a `lan` `(address, port)` passes; anything else needs a live grant whose addresses contain it and whose port matches. Resolution: the guard's `loop.getaddrinfo` answers a granted host from the grant's recorded addresses; `egress` resolves once per grant under a resolution grant; a blocking `getaddrinfo` of a protected name outside a grant raises. Sockets opened by subprocesses are not prevented (stated).

**D3 The `lan` class (T9) [beyond ADR in detail].** Entries are `(resolved address, port)` per service, built at install from `GO2RTC_URL`, `FRIGATE_URL`, `GATUS_URL`, MQTT and every `go2rtc_url` in `config/devices.yml`; a non-private address is not `lan` (a public `GATUS_URL` is an `ops` destination). A gateway port wins over a `lan` entry on the same address, including when two configured names resolve to one address (tested). A DHCP change needs a restart (stated).

**D4 Destinations registry [beyond ADR in shape].** `privacy/destinations.py`: one frozen record per destination — name, scheme, hosts, port, purposes allowed, `locality` (`cloud` | `local` | `lan`), allowed request headers, a redirect policy (D16), and for `ops` and `notify` a request schema (method, path pattern, the fields and how each is encoded). Initial set: `anthropic`, `magpie`, `ollama` (local only when the configured `backend:model` is on `LOCAL_MODELS`, else refused for learner text; the existing measurement gate kept), `edge_tts`, `telegram` (`notify`, `ops`), `bark` (`notify`), `healthchecks`, `gatus`, `ollama_probe` (`GET /api/tags`), `magpie_probe`, `openlibrary`, and the download hosts (`github` with its asset hosts, `raw_github`, `huggingface` with its CDN hosts, `osf` with its storage host, `cambridge`, `openslr`, `spacy_models`, `rapidocr_models`). A host no destination lists is refused.

**D5 Purposes, ownership of attempts, and the notification (T1, R1, R25) [one name beyond ADR].** ADR-0018's study purposes plus **`notify`**. Migration 6 (D19) adds `notify` to `egress_log.purpose`'s CHECK. `learner_id` stays required for study purposes: a send before identification is attributed to the session's guest row, a catalog lookup outside a session to `anonymous`. Ownership: `identify.adopt()` re-keys the guest's `egress_log` rows to the adopted learner in the same transaction that re-keys its other rows; the guest's outstanding tokens fail revalidation (its source is gone). `run_session` discards a guest only after `deliver` and every egress of the session has finished. `finalize()` sets `ended_at` and `summary` before delivery, so neither can mark the end of a session's egress (U3). Migration 6 adds `reading_sessions.post_done_at`, written by `run_session` after `deliver` and `extract_notes`; `finalize_guest` moves out of `finalize` to after that write. The guest sweeper and `forget` treat a session as disposable only when `post_done_at` is set. Startup recovery sets it for ended sessions whose owning process is dead (the pid and start-time test of D8; `reading_sessions` gains the same `owner` column), so a crash or a busy final write never leaves a learner unforgettable or a guest unsweepable. A test races the sweeper against a delivering session, and another kills the process between `finalize` and `post_done_at`. The ports `Notifier.notify` and `Catalog.lookup` take `learner_id` and `session_id`.

The notification is built by construction, not passed as a string: `privacy.notification(learner, counts)` renders a fixed template whose only variables are the learner's surrogate (D10) and integer counts; `notifiers.notify` accepts only that object, and the `notify` request schema has exactly those fields. Owner decision 2026-10-23: the surrogate is sent. For a guest, or a learner with `cloud.text` off, the template has no surrogate ("a reader"). ADR-0018 §6 ("study notifications deferred") is amended in M5c to describe this one exception and its schema.

**D6 Binding a token to the bytes sent (T5, T6, R5, R6) [beyond ADR in detail].** `prepare(destination, purpose, request, learner, session, sources)` takes the request **as fields**, before any encoding: method, scheme, host, port, path template and its text fields, query, allowed headers, and a JSON or form body. It filters each text field (provenance, pseudonymisation), then encodes them itself — URL-quoting Bark's title and body into the path, form- or JSON-encoding the rest — rejecting JSON with duplicate keys, non-finite numbers or invalid UTF-8, and returns the request with the exact bytes to send (canonical: sorted keys, compact separators, UTF-8; sorted form and query pairs). The token records `H = HMAC(secret, scheme, host, port, method, encoded path, encoded query, allowed headers, body bytes)`.

The token id is attached to the specific request: the adapter passes it as the header `x-leafi-token` (the anthropic SDK through `extra_headers` on that one call; httpx2 adapters on the request), and the mediating transport removes the header before hashing and sending, so it never reaches the wire. The transport then checks the outgoing request against the prepared one and refuses on any difference, on a header outside the allow-list, or on a body it cannot read (streaming, multipart) for study purposes. For httpx2 adapters Leafi builds the request, so the outgoing bytes are the prepared bytes exactly. For the anthropic SDK, which serialises JSON itself in insertion order (S29), the transport parses the SDK-built body with the same strict parser (duplicate keys, non-finite numbers and invalid UTF-8 refused), compares the parsed value with the prepared value, computes `H` over the canonical form of that value, and sends **the SDK's bytes it just parsed** — the bytes checked are the bytes sent. Headers: each destination lists the header names it accepts and, for those carrying meaning (`content-type`, `anthropic-version`, `anthropic-beta`), the exact values; the SDK's own `user-agent` and `x-stainless-*` headers are accepted by name with a value pattern that admits no free text; any other header is refused. The real-SDK positive control (an offline probe of `anthropic==1.17.0` through the transport to a fake server) is the first test of M5b and gates D6.

**D7 Tokens (T5, R5, R21).** `privacy/tokens.py`: an in-process store under a `threading.Lock`: `Token(id, learner, session, purpose, attempt_id, sources, versions, expires, transmissions)`. On the transport's first entry with an id, the token is removed from the store atomically; the transport invocation holds it privately and uses it for the first transmission and, for text, one retry on connect errors and 5xx (tenacity waits inside the expiry); it is burnt on every exit. A second entry with the same id, the same request object included, finds nothing and gets 403. Media: no transmission in M5 (D20); `ops` one per hop. Adapter retry loops are removed (`claude.py`'s loop; SDK `max_retries=0` kept). Expiry gates connect and consumption only; a download stream has its own read timeout. Expiry = the call's deadline (`brain_call`'s, 30 s for `tts`, `notify`, `catalog`, 120 s per download hop). Before each transmission, the retry included, the transport revalidates (D12) and calls the budget hook (ADR-0017 §5; a no-op until M7). Guard denials (`NetworkDenied`) raised inside the transport are converted to 403 before the retry classifier sees them, so a refusal is never retried.

**D8 The secret and the log (T18, R18).** `data/egress.key`: 32 bytes from `secrets.token_bytes`, written to a temporary file and linked into place with `os.link` (the loser reads the winner's file); any length but 32 fails closed with an alert; included in `leafi backup`. The `egress_log` row is written before transmission (`sending`, with `owner` = the writing process's id and start time, a column of migration 6). Before each transmission, the retry included, `transmitted_attempts` is incremented and committed (a reservation: "may have been sent"), and only then are bytes written; afterwards the row is updated to `sent` / `failed`, or `unknown` on cancellation, in `finally` (S18). A process killed between the two writes leaves `sending` with the count of attempts that may have left; recovery marks it `unknown` and keeps the count. A test kills a child process between reservation and outcome. At startup a process marks `unknown` only `sending` rows whose owner process is not alive (pid absent, or alive with a different start time). Bodies are never stored. `ops` rows older than `PRIVACY_OPS_LOG_DAYS` are deleted at session start and by the supervisor's daily pass.

**D9 Refusals (T21, R21).** Pipeline, token and guard refusals inside a mediating HTTP transport return `httpx2.Response(403, json={"refused": reason})`, so httpx2 adapters handle one shape and the SDK maps 403 to `PermissionDeniedError`, which it does not retry. Outside HTTP (aiohttp in library-mode edge-tts, raw sockets) the guard raises `NetworkDenied`; `TtsService` and the edge adapter catch it and show the line on Faces.

**D10 Pseudonymisation (T3, T4, T19, R3, R4, R24) [surrogate choice beyond ADR].** Lists, applied to **every** text class (page text included): every `learners.display_name` and alias (all kinds but `anonymous`; an alias joins its learner's entity), every `household_terms.term` (forgotten learners' names and aliases, added at forget; schools; others). Terms and input are NFC-normalised and casefolded for matching. A Latin-script term matches where it is not adjacent to another Latin letter or a digit (so `我叫Ann今天` matches, "Annie" does not), with straight and curly possessives and hyphen parts; a CJK term matches as a substring; longest term first.

Surrogates: one per person entity, allocated on first need in a transaction by probing `HMAC(secret, "surrogate:" + entity)` through a bundled list of ~200 neutral first names that are not English dictionary words; stored in `pseudonyms(entity UNIQUE, surrogate UNIQUE)` (D19), where `entity` is `learner:<id>` while the learner exists and `former:<id>` after forget, `<id>` being the same learner id that every retained `household_terms` row of that person carries in `former_learner_id` (forget writes the name and every alias with it and renames the entity in the same transaction, S24). All of a forgotten person's terms therefore keep one surrogate; the row is deleted when the last term with that `former_learner_id` is removed. Tests: name and alias of a forgotten learner map to one surrogate; removing one of them keeps it; removing the last deletes it. Every `prepare` rechecks the request's surrogates against the current protected terms: a surrogate that has become a real household name is reallocated and the change logged. Pool exhausted → `[name]`. If a payload contains an entity's surrogate as a word, that request uses a one-off alternate recorded in the token's mapping; notifications (D5) always use the stored surrogate, so the parent's mapping stays stable. The detector (D11) runs on the original text before substitution and its spans are merged with the list spans, so an inserted surrogate is never detected again. The reply is mapped back only for person surrogates sent in that request, case-sensitive, whole word; neutral tokens ("the school", `[place]`, `[name]`) are never reversed. A school becomes "the school", `other` terms `[place]`.

Schools and age: ADR-0018 §3 requires each learner to have a school name or an explicit "no school" (S19). The answer is the learner privacy key `privacy.school` — `none` or the id of a `household_terms` row of kind `school` (siblings at one school share the row) — written by the privacy writer with a `privacy_version` bump (U6a). Voice enrolment in `identify` asks for it; a "don't know" or a timeout still creates the learner, with the key unset. While it is unset, that learner's learner-derived text is refused to the cloud (refused, not sent unprotected), and `leafi doctor` and the console list who is missing it. A voice answer is ASR text from a child, so `doctor` and the console show each recorded school for the owner to confirm or correct (U6c). `leafi privacy learner <name> school "<name>"|none` sets it from the CLI; given a name already in `household_terms` under another kind (an imported `REDACT_TERMS` school, which `doctor` used to tell owners to add), it changes that row's kind to `school` and links it, instead of colliding with the unique index (U6d). Owner decision 2026-10-23: age is protected in the structured profile only — the system prompt says "a child aged <band>", the band computed at prepare from `birth_year` (unknown → "a young learner"); ages inside learner free text are sent as they are. ADR-0018 §2 ("exact ages never") and its canary are amended in M5c to say so.

**D11 The detector (T14, R14).** Presidio `AnalyzerEngine` built by Leafi: `spacy.load("models/spacy/en_core_web_sm-3.8.0")` wrapped in Presidio's `NlpEngine` interface, and a `RecognizerRegistry` holding only the spaCy recognizer (`PERSON`, `ORGANIZATION`, `LOCATION`); no predefined recognizers are imported, and `tldextract` is configured with no suffix-list fetch in case a dependency imports it. A test builds it under `LEAFI_NO_NETWORK=1` in a subprocess and asserts no subprocess and no connect. Versions: `presidio-analyzer==2.2.364`, `spacy==3.8.16` (MIT), model `3.8.0` (downloaded and unpacked by `doctor --download`). It runs on `learner` / `derived_from_learner` text when `PRIVACY_NAME_DETECTOR` is on; entities become `[name]` / `[organisation]` / `[place]`. Owner decision 2026-10-23: the model missing while the detector is on degrades to list-only replacement. `leafi doctor` and the settings page show the effective state ("on", "on, model missing: list only", "off") apart from the configured value. ADR-0018 §3 and Confirmation are amended in M5c: the unlisted-school-and-friend canary holds when the detector is available; list-only mode has its own canary (listed terms only) and is not reported as meeting the detector guarantee. Recall on household transcripts is measured before anyone claims completeness.

**D12 Settings and revalidation (T16, T17, R17).** Learner privacy keys `cloud.text` (on) and `privacy.media` (ask) live in `learners.settings` but are written only by `privacy/settings.py`, which writes the value, bumps the learner's `privacy_version` and writes a `consents` row for `cloud.text` in one transaction; `harness/settings.SPEC` rejects them; guests read as off whatever is stored. Household keys (`.env` manifest): `CLOUD_PARENT_TEXT`, `PRIVACY_TTS_LEARNER_LINES`, `TTS_EDGE_MODE`, `PRIVACY_NAME_DETECTOR`, `LOCAL_MODELS`, `MAGPIE_URL`, `PRIVACY_OPS_LOG_DAYS`, `HOUSEHOLD_TZ`; † keys join `envprotect.PRIVACY_FLOOR`. Owner decision 2026-10-23: the confirmation stays the settings page's checkbox bound to the value's hash; ADR-0018 §5 and §6's "typed confirmation" become "explicit confirmation bound to the value". The CLI shows the resolved learner, the operation and the exact value and asks yes/no before the transaction.

Versions (`privacy/versions.py`): a per-learner `privacy_version` and a household `protected_version` (bumped in the same transaction as any change to `household_terms`, learners, aliases or forgetting), both in the database (D19); and a **policy fingerprint** for the household keys, which live in `.env` and so cannot share a transaction with the database (S32). The fingerprint is the HMAC of the effective values of the privacy keys — the `.env` file's values with the process environment's overrides applied, exactly as `Settings` resolves them — computed when the process loads its settings. No counter is written anywhere, so there is no two-store publication to crash between.

`prepare` reads the lists, the source learners' settings and both database versions in one SQLite read transaction (one snapshot), filters with them, and stamps the token with those versions and the process's fingerprint (S33). The **admission point** is immediately before each transmission, the retry included: the transport rereads both versions (one indexed read, no lock held across network awaits) and recomputes the fingerprint from the current `.env` file (cached by mtime and size) and the process's overrides; it refuses if a version differs, a source is missing, is a guest whose adoption moved it, has `forgetting = 1`, or the fingerprint differs from the process's (a running process whose `.env` changed refuses learner-derived egress until it restarts; the settings page restarts the services it runs; a manually launched process is refused, not trusted). A transmission admitted before a concurrent policy change in another process may complete — the window is one request, and is stated in security.md; stricter revocation is not required by ADR-0018. Tests: a version bump between `prepare` and admission refuses; a `.env` edit while running refuses; an environment override is part of the fingerprint.

`REDACT_TERMS` → `household_terms`: imported in M5a (D19) — each term of kind `name` (the conservative default: a name gets a surrogate; no prompt, since `migrate` also runs from a console button without stdin; the school command above corrects a school later), `INSERT OR IGNORE` against the unique index, a term already a learner name skipped. Until M5d removes the key, the list reader reads both, so no caller loses a term at the switch-over. M5d's removal first runs the same import again, idempotently, against the effective `REDACT_TERMS` value — catching terms added since migration 6 and databases created fresh at version 6, which never ran it — and clears the key only after the import commits (S2); both paths are tested. The `redact-terms` alert becomes `household-terms`.

**D13 Provenance at the TTS call (T10, T11) [replaces `local_only`].** `Inputs.say(text, *, provenance)` and the `Talk` protocol take provenance (class and source learner ids) as a required keyword; static phrases go through `say_phrase(key)` (class `system`). `phrases.line(key, **kwargs)` returns the text with the most restrictive class of its kwargs, and the union of their sources. Provenance travels through `ListeningGate`, `Hub` and the `Synthesizer` port unchanged. Identification lines are `learner` until adoption; Anki card text restores the stored card's provenance (unknown → `learner`). A test enumerates every `say` / `line` call site. Routing, after the existing per-language backend choice: with `PRIVACY_TTS_LEARNER_LINES=local`, a `learner` / `derived_from_learner` line, or any line containing a list term or a detected entity, goes to the local backend (Kokoro; none → Faces only), so with `local` edge-tts never speaks a surrogate (ADR §2; with `cloud` it may, as the ADR allows); the rest goes through `prepare(edge_tts, "tts", ...)`. The TTS cache writes the provenance sidecar on hits and misses. `local_only` and `LocalOnlyUnavailable` are removed.

**D14 edge-tts (T12).** `library` mode (default): per line `prepare` writes the attempt row and opens a connection-level grant to the edge-tts host for that call; the library runs inside it with `trust_env` off and aiohttp's `ThreadedResolver` (a patched `ClientSession` factory), and the session is closed at the end of the call. `mediated` mode: a Leafi adapter reusing only `edge_tts.drm` and `edge_tts.constants` from `edge-tts==7.2.8`; it prepares the whole line, chunks the prepared text, derives one token per chunk carrying the line's sources and mapping, opens the WebSocket through `egress.ws_client("edge_tts")` with `allow_redirects=False`, and wraps `send_str`: the SSML frame must match a fixed template whose only variable part is the chunk, whose HMAC must match the chunk's token; config frames are a fixed schema; no retry. An offline test renders the library's frames and the adapter's for the same text and asserts them equal.

**D15 Third-party clients and the environment (T13, T15, T22, R13, R22).** `leafi.bootstrap.install()` sets `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`, `HF_HUB_DISABLE_TELEMETRY=1`, `HF_HUB_DISABLE_XET=1`, `DO_NOT_TRACK=1` and Ultralytics `sync` off before any hub import. These settings take effect in M5c, with the HF child below, not at M5a (S28). HuggingFace downloads run only in a child process started by `doctor --download` as `python -m leafi.hf_download <repo> <revision> <dir>`. The parent launches it with an environment from which `HF_HUB_OFFLINE`, `TRANSFORMERS_OFFLINE` and `HF_DATASETS_OFFLINE` are **removed** (S22); the child's first statement is `install(hf_download=True)`, which leaves them removed, installs the guard, and only then imports `huggingface_hub`, setting `set_client_factory` to a client whose transport is an **HF adapter**. The adapter prepares every request itself. An **initial** request must match a fixed schema (`HEAD` and `GET` on `/<repo>/resolve/<revision>/<file>`, `GET /api/models/<repo>/revision/<revision>`, for the named repos only). A **continuation** is allowed only as the target of a redirect or a `Location` the adapter itself validated in an earlier response for that file: the adapter records a capability bound to the exact absolute URL, the file and the method (`HEAD` → `GET` allowed, as the library does), valid until the file's deadline, within the chain's hop count (≤ 5), to the CDN hosts listed per destination (`cdn-lfs.huggingface.co`, `cdn-lfs-us-1.hf.co`, `cas-bridge.xethub.hf.co`, confirmed against the fake-hub test and a recorded real redirect before M5c), with `Authorization` stripped on an origin change (S13). huggingface_hub 1.16.1 resumes a broken GET on the same URL with a new `Range` up to 5 times and re-sends on 429 (`file_download.py` 439–458), so a capability may be used again only for a GET whose `Range` starts at or after the bytes already received, or for a 429 retry, at most 8 uses (U4). `op.HF_REPOS` pins each repo to a commit sha, and the child is given the sha, so the `/api/models/<repo>/revision/<sha>` and `/<repo>/resolve/<sha>/<file>` requests match the schema (`snapshot_download` resolves with `repo_info.sha`). Leafi's client factory keeps `follow_redirects=False`; the library's relative-redirect helper issues the next hop itself, which the adapter checks as a continuation. Everything else is refused. Nothing else in that process sends. A test runs a real worker-driven download of two files concurrently against a local fake hub with a relative redirect, an absolute CDN `Location` and a resumed range request, launched from a bootstrapped parent. RapidOCR: its model files are fetched by Leafi's mediated downloader into `models/rapidocr/` and the engine is pointed at local paths; a test asserts no `requests` session opens. Subprocesses: a monitor-only audit hook logs every `subprocess.Popen` with its executable. `doctor` asserts `aiodns` is absent.

## Decisions

### Privacy: locality, provenance, the filter

**D1 Effective locality, one resolver, bound to the request [beyond ADR; closes an M5 gap, T1, R1].** A `Destination` gains `model_bound: bool`, true for destinations that accept a Brain purpose and are not registered `cloud` (today only `ollama`; magpie is registered `cloud`, so it is not model-bound and is always gated, S9). `leafi.privacy.destinations.effective(dest, model) -> "cloud" | "local" | "lan"`:
- `model_bound` false → the registered locality, unchanged (`anthropic`, edge-tts, catalog, notifiers, heartbeat, alerts, downloads, and the ops-only local destinations `gatus` and `ollama_probe`, which carry no learner text and no model);
- `model_bound` true → `local` only when `f"{backend}:{model}"` is on `LOCAL_MODELS`, the model is not an Ollama cloud-hosted name (a `-cloud` suffix or a `:cloud` tag, refused as local even when listed: ADR-0018 §2), and the destination's host is a loopback **literal** (`127.0.0.0/8`, `::1`) or `localhost`; else `cloud` (S9: a hostname resolving to "this machine" at `prepare` time could resolve elsewhere at `_transmit`; a LAN Ollama is therefore treated as cloud until a later design admits it). Model names are compared exactly: `qwen3` and `qwen3:latest` are different entries, and a mismatch fails safe to `cloud` (documented in `config.md`). Name-based detection of Ollama cloud models is a heuristic; a `doctor` probe of Ollama's model metadata is deferred to M10 with the Ollama measurement.

`prepare(…, model: str | None = None)`: for a `model_bound` destination `model` is required, and `prepare` refuses unless the body's own model field (`json["model"]`) equals it, so the checked model is the one sent; `effective()` is computed there and stored on the `Token` with the model, and the mediating transport refuses a request whose parsed body names another model (the existing body comparison already covers it; the token makes the reason explicit). Routing's `eligible()` (D10), the filter (D3) and the `brain_calls` row read the same resolver. Callers updated in M7a: `services/brain/ollama.py`'s v1 `run` passes its model; `claude.py` passes its model (its destination is `cloud`, so the value is logged, not decisive); every other caller is unchanged. Provenance: *adapted* from ADR-0018 §2 ("local only when on `LOCAL_MODELS`; Ollama's cloud-hosted model names are refused"), which M5 did not enforce. First commit of M7a, with `test_privacy` cases: an Ollama model not on the list is pseudonymised and gated; a listed `…-cloud` model is cloud; listed but on another host → cloud; body model ≠ `model` → refused; `ollama_probe` and `gatus` unaffected; a guest, a forgotten source and mixed-source text each refused or filtered as cloud; a learner with `cloud.text` on and **no school answer** sent, pseudonymised by the lists and the detector (A1, owner 2026-10-24: the school answer no longer gates a learner's words; `privacy.settings.cloud_text_allowed` drops `school_answered`, and `_gate`'s "no school answer" reason goes with it, in M7a).

**D2 One provenance type; provenance follows every output as a set of restrictions [beyond ADR in mechanism, T3, T24, R2, R10].** `Provenance(cls, sources)` moves to a new import-free module `leafi/core/provenance.py`; `leafi.core.ports` and `leafi.core.text` import it from there (no cycle: `core.text` already imports `ports`), and `leafi.privacy.egress.Text(value, provenance, sources)` keeps its constructor and gains `.prov -> Provenance`. One type for TTS routing, egress and storage.

A single "strongest class" cannot carry two independently configured permissions (a learner's `cloud.text` and the household's `CLOUD_PARENT_TEXT`), so an **output's** provenance is the conjunction of its inputs' restrictions, encoded in the existing columns:
- **Raw input** keeps its exact class: the learner's own words are `learner` with that learner as source; a stored note is `derived_from_learner` with its sources; parent text is `parent`.
- **Every Brain output** (`say_before`, rationale, answers, explanations, quiz text, cards, translations, assessments, notes, book notes) gets `Provenance.of_output(sent)` over the leaves **actually sent to that backend**: class `derived_from_learner` when any sent leaf is `learner` or `derived_from_learner`, else `parent` when any is `parent`, else `page` when any is `page`, else `system`; **sources** = the union of the learner sources, plus the reserved source id **`0` = "parent origin"** when any sent leaf is `parent` and the class is `derived_from_learner`.
- `learner_store.PARENT_SOURCE = 0` is the one definition (learner ids start at 1; `0` is never a learner). **Every reader of sources treats it as a flag, not a learner (S1):**
  - `egress.prepare`: `parent_origin = PARENT_SOURCE in leaf sources`; the `sources` set it builds for `versions.snapshot`, the privacy map and the egress log excludes `0` (so `admit`'s `versions.stale` never sees a missing "learner 0");
  - `_gate`: **first**, a leaf with source `0` is refused for a cloud destination unless `CLOUD_PARENT_TEXT` is on; then a `learner` / `derived_from_learner` leaf with **no non-zero source left** is refused (as a leaf without sources is today: `(0,)` alone names no learner, round 4 #10); then the existing per-source loop over its non-zero sources;
  - `learner_store.stated_sources`, the `sources=` argument of every fenced write, and the fence's `COUNT(*) … = ?` exclude `0` (D22's `named()`);
  - `records._purge_derived`'s `json_each(source_learners)` never matches `0` (unchanged).
  So a mixed output leaves only when every learner source allows it **and** parent text may leave; to a local backend it goes as usual. Tests: `test_privacy` through `prepare` **and `admit`** for a local and a cloud destination with a `[A, 0]` leaf (`CLOUD_PARENT_TEXT` on and off); `test_learner_store` (insert with `[A, 0]` accepted, refused once A is marked).

Outputs are stored in the row's provenance columns, spoken with it (`Talk.say(…, provenance=…)`, so TTS routing keeps them local when required) and re-observed with it. Test: a local tier given a parent leaf (with `CLOUD_PARENT_TEXT` off) and an allowed learner's note produces an assessment that a later cloud call withholds; a local tier copying a learner note into an assessment keeps that learner as source. Provenance: *adopted* from ADR-0018 §3's classes; the output rule and source `0` *original*.

**D3 The filter is per leaf [beyond ADR in form, T16].** For each call, every `Text` leaf of the observation (of every `Turn` of a multi-turn request, re-rendered at each request, D5) is checked with `egress.may_send(dest, model, text, learner_id)` (the gate `prepare` runs, made public: `_gate` behind D1's resolver). A refused leaf is replaced by its **substitute** when it has one — a heard word becomes `{expected word, category}` (ADR-0018 §2's "expected words + category"), a learner note becomes nothing — and its section records `withheld: n`. Kinds, statuses, counts, difficulty keys and page text survive. `answer` and `judge` carry the learner's words as their payload, so for them the check is eligibility (D10): no eligible backend → the call is not made. A settings change between the filter and `prepare` makes `prepare` refuse; the call is recorded `refused` (T24).

**D4 Rejection feedback is codes only [T2].** After an invalid shape, the next tier's request gains one `system` line built from a fixed vocabulary: `rejected: <code> at <field path>` for each failure (codes: `missing`, `type`, `too_long`, `too_many`, `unknown_id`, `not_in_menu`, `unsupported_answer`, `url`, `truncated`, `refusal`), with paths from the schema and ids that the observation sent. Never a value, a Pydantic message or an exception string. Provenance: *adapted* from LiveKit's `ToolError` re-ask (research R9), narrowed to codes.

### The call layer

**D5 Layering and the backend port [beyond ADR, T6, T11].** The harness side lives in `leafi/study/brain/`: `schemas.py`, `observe.py`, `prompts.py`, `routing.py`, `call.py`, `scoring.py`, `items.py`, `records.py`, `arms.py`. The port is a `typing.Protocol` in `leafi/core/ports.py`:

```
ModelRequest(purpose, model, system: str, turns: list[Turn], schema: dict, max_tokens, effort,
             thinking: "adaptive" | "off", timeout_s, learner_id, session_id, budget: Budget,
             attempt: CallAttempt)                       # a fresh CallAttempt per backend call (round 5 #12)
Turn(role: "user" | "assistant", sections: list[Section], provenance: Provenance | None)
    # single-turn purposes send one user Turn; a multi-turn purpose (M7f's practice_turn, C1) sends the
    # whole conversation, each assistant Turn carrying D2's output provenance; no tool calls, no tool results
Section(name, texts: list[Text])
CallRecord(outcome, value: dict | None, sent: dict | None, received: str | None, model, provider, usage,
           latency_ms, transmissions, stop_reason, provenance)
    # outcome ∈ ok | invalid | refused | over_budget | timeout | failed | cancelled
class BrainBackend(Protocol):
    name: str
    async def call(self, req: ModelRequest) -> CallRecord          # never None; cancellation: see D8
    async def reset(self) -> None                                    # aclose the mediated client, build a new one
```

`over_budget` and `refused` are read from egress's synthetic 403 body (`{"refused": reason}`). **A cancelled call cannot return (round 4 #4):** `ModelRequest` carries a mutable `attempt: CallAttempt`, a new one for **each** backend call of the walk (so a later tier never overwrites an earlier tier's record, round 5 #12), which the backend fills right after `prepare` succeeds (`sent` payload, `egress_attempt_id` from the new `Prepared.attempt_id`, which `prepare` already knows as the `egress_log` row id, `model`); the walk, not the backend, classifies an exception (`TimeoutError` from its own `fail_after` → `timeout`; the latch's cancellation → `cancelled`) and builds the `CallRecord` from the attempt, reading `transmitted_attempts` from `egress_log` by `egress_attempt_id`. A call cancelled before `prepare` has no attempt and no row. The composition root builds the tiers (D9) and gives `Session` a `Brain` (tiers, routes, backends); the harness never imports a backend. **Bridge (R10): the compatibility surface M7a keeps until M7e, each item named so it is removed on purpose:**
- `services/brain/claude.py` and `ollama.py` keep `run(BrainRequest)` beside `call(ModelRequest)`, both through egress and both passing `model` to `prepare` (D1);
- `Settings.brain_deadline_s`, `study_brain_model`, `brain_model_cheap`, `brain_local_model` stay readable as deprecated properties: `study_brain_model` = the first model of `BRAIN_TIER_DEEP`, `brain_model_cheap` = of `BRAIN_TIER_FAST`, `brain_local_model` as D9 defines it (S6), `brain_deadline_s` = 12.0 (no longer a `.env` key), so the legacy constructors and `doctor`'s status lines keep working;
- `leafi.privacy.egress.Text(value, provenance: str, sources)` keeps its constructor (D2), so edge-tts and every M5 caller is untouched;
- `Session.generate` and `Session.routable_answer` stay as properties computed from `s.brain` (`menu.allowed` and `construct` read them) until M7c converts those readers. Because they become non-empty in M7a, **the same commit** adds the handler gate to `menu.allowed` (a kind is allowed only when `activities.KINDS` has its handler; today `quiz`, `learner_questions`, `teach_items` and `recall_items` have none, so a learner naming "questions" is told it cannot be done instead of reaching `KINDS[…]`'s `KeyError`) and makes `construct`'s `brain`-owner branch return `Rejected("not available now")` until M7c replaces it with validated generation (today it takes `spec.content` unvalidated) (S6).

Until M7e `coach.py`'s remaining callers stay green; M7e deletes `run`, `BrainRequest`, `SCHEMAS`, `validate`, `build_prompt`, `SYSTEM`, and moves the page helpers `coach.py` still serves (`find_on_page` and `sentence_text`, used by `harness/activities.py`) to `leafi/study/pages_text.py` before deleting `coach.py` (T11).

**D6 Schemas [beyond ADR, T12, T13, T15].** Pydantic v2 models. Unions are plain `Union[...]` (never `Field(discriminator=…)`, which emits `oneOf` + `discriminator`); each member has `kind: Literal[…]`. `api_schema(Model)` walks the generated schema recursively: keeps `type`, `properties`, `required`, `items`, `enum`, `const`, `anyOf`, `allOf`, `$ref`, `$defs`, `description`; drops `minLength`, `maxLength`, `minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum`, `multipleOf`, `minItems`, `maxItems`, `default`, `title`, `pattern`, `format`; closes every object; **raises** on anything else (`oneOf`, `not`, `if`, recursion), so an unsupported construct fails a unit test, not a session. `anthropic.lib._parse._transform` is not used: it is private and its output would have to match egress's body comparison byte for byte across SDK upgrades. Pydantic still enforces every dropped constraint after parsing. `tests/test_brain_schemas.py`: every purpose's exact schema passes `api_schema`, counts its optional and union-typed parameters against the vendor limits, is byte-identical when built twice, and the SDK body equals the prepared body (nulls, `$defs`, non-ASCII). Before the gate of M7b opens a real call, one compilation probe per schema runs against the API with the owner present (step M7b).

**Two-level validation (T13).** The `decide` output parses in two levels: the **envelope** (`activity.kind`, its selection fields, `alternative`'s kind and selection, `turn`) strictly — a failure is `invalid` and escalates; then **each** of `say_before`, `rationale`, the activity's content fields and each record separately — a failure drops only that part (content falls back to construction's `generate` or the default content owner; a record is logged and dropped, ADR-0017 §7.1). Selection fields are small and closed, so their schema stays inside the vendor limits; content fields are typed loosely in `decide` (strings and lists) and validated by their kind's model at construction.

`max_tokens` and thinking (T15): `decide`, `judge`, `word` run with thinking `off` where the model allows it (Haiku 5.5 at effort `low`; Sonnet 5.5 via `between_tools`, which for a no-tool call is thinking off) and adaptive at effort `low` on Opus 5.5 (it cannot be off); `max_tokens` decide 4,096, generate 8,192, answer 2,048, judge 2,048, word 1,024 (headroom for thinking; the reply's own length is bounded by the schema's fields and Pydantic). A `max_tokens` stop is `invalid` with code `truncated`. Effort per (purpose, tier) in `prompts.py` (*untuned*), constant within a session; the schema bytes, system text and effort are frozen per `PROMPT_VERSION`; the compiled schema is reused across sessions by the vendor's 24 h schema cache (O3: no warm-up request), which is separate from prompt caching below.

**Rendering order and the prompt-cache breakpoint (T23, R12), the one statement of it.** A request is rendered in this order, stable first:
1. `system`: the frozen rule text of `PROMPT_VERSION` (voice, data-not-instructions, the no-correction-while-reading rule, praise rules), then the learner's policy text (settings, autonomy level, age band; stable within a session). **One `cache_control: {type: "ephemeral"}` breakpoint on the last `system` block.**
2. The user message's sections, in this order: `page` (book, printed page, sentences with ids), `memory` (difficulty keys, notes, familiar books), `cycle` (candidates, new items, recall due), `menu` (allowed kinds, default chain), then the volatile ones: `last_activity`, `session` (elapsed, deadlines, ledger remainders, `withheld` counts) and `turn` last.

The breakpoint sits on the system text only: the page and cycle sections change at most boundaries, and a second breakpoint after them would pay cache writes it rarely reads (*untuned*: M10 reads `cache_read_input_tokens` from `brain_calls` and may add one). Below the 512-token minimum nothing is cached and nothing fails. `test_brain_call` checks the rendered request's order and the single breakpoint. **Multi-turn purposes (C1, C3):** a request with several `Turn`s renders them in order after `system` and may carry **one more** breakpoint, on the last block of the first assistant turn (for M7f's practice, the plan), so the rest of an activity's conversation reuses it; still at most two, both measured in M10. Single-turn purposes keep exactly one.

**D7 Budget: charge exactly once per reserved transmission [beyond ADR in placement, T5].** `Egress.prepare(…, budget: Budget | None)`, stored on the `Token`. `Budget` has `can_cover() -> bool` and `charge()`. In `admit`, the existing order is kept and extended (R3, S10): **inside each attempt of the retried `BEGIN IMMEDIATE` reservation transaction**, the household fingerprint check (moved inside: today it runs once before the loop), the version check (as today), `budget.can_cover()` (pure: a refusal rolls back and returns a synthetic 403 `over budget`), and the reservation write; commit; **then one synchronous, non-awaiting `budget.charge()`**, outside the retry loop, before the transmission starts. A busy attempt rolls back and repeats every check, so a privacy or budget change during the wait is seen; a stale-versions refusal charges nothing; a busy retry never charges twice.

This is **reservation accounting**: a cancellation after the commit but before any byte leaves (during DNS or connect) has been charged although nothing was sent. ADR-0017 §5 says a cancelled call "has already been charged for what it sent"; Leafi charges what it reserved, which is never less, and the `brain_calls` row records `transmitted_attempts` (reserved) so the difference is visible. Recorded in ADR-0017's `revised` note in M7a. The session's `Budget` charges `TIER_COST[tier]`; the post-session context's `Budget` counts **calls** against `limits.extract_calls` 2 (not tier-weighted, so `deep` is affordable): it charges 1 on a call's first transmission and 0 on the mediator's retry of that call, so one retried call spends one of the two (T24, S10). The process-wide `Egress.budget` hook stays for tests and is ignored when a token carries its own. Test: busy reservation (one charge), a privacy version change while the reservation waits (refused, no charge), stale versions, cancel after commit (charged, `transmitted_attempts` 1), cancel before commit (no charge), the mediator's retry (charged again, once). Provenance: the per-token hook *original*; reservation before transmission *adopted* from M5 D7.

**D8 `brain_call`, deadlines, cancellation and audit [ADR §5 filled in, T6, T14].** One absolute **moment deadline** per boundary or answer (`moment(s, name)`, D12) is passed to `decide` and every `generate` of construction; nothing restarts it per candidate or per tier. The route is walked **in its order** (ADR-0017 §5's loop over tiers and their eligible backends); what an outcome changes is only which remaining entries are tried first and which are skipped (R4):
- `invalid` → the next entry in route order (with the rejection codes of D4);
- `timeout` → among the remaining entries, those whose `MIN_TIER_S` fits the remaining moment, tiers **not slower** than the one that timed out first, then the others in route order; a tier is never retried after its own timeout within the same call;
- `refused`, `over_budget`, `failed` → the next eligible backend of the same tier, then the next entry in route order;
- any entry whose `MIN_TIER_S` exceeds the remaining moment, or that the ledger cannot cover, is skipped; the walk ends when the route is exhausted or the moment is spent.

**`prepare` is synchronous and must stay cheap inside the walk (round 4 #5, round 5 #11).** Its one slow step, loading the name detector (spaCy, ≈ 8 s here), moves off the event loop with an explicit state:
- `Egress.detector_state` ∈ `unloaded | loading | ready | off` behind a `threading.Lock`; `Egress.start_detector()` moves `unloaded → loading` once and loads in a worker thread (`anyio.to_thread.run_sync` from async callers, a plain thread from the CLI), ending `ready`; a second call while `loading` does nothing;
- **every Leafi process that may prepare learner text calls `start_detector()` at process start** (the study runner before the lease, the replay script, the settings page's test send), so a study session normally finds it `ready` by the first boundary; no dead air after identification;
- **inside a session**, `prepare` never loads: with the state `loading` or `unloaded` it refuses learner-text leaves for a cloud destination with `detector not ready` (the call falls back like any refusal);
- **outside a session** (the CLI, `doctor`, a test send) `prepare` keeps M5's behaviour: it waits for the load (blocking is acceptable off the event loop), so M5's callers are unchanged;
- `test_brain_call` bounds `prepare` at 50 ms in the real-clock walk; `test_egress` covers the four states and a `prepare` during `loading`.

**Per-call limits are per (purpose, tier) (S4) [beyond ADR: ADR-0017 §5.2's `PER_CALL_S` is per purpose, *untuned*]:** `decide` fast 2.0 s, standard 3.0 s, deep 4.0 s; the other purposes keep the ADR's value on every tier. `MIN_TIER_S` (fast 1.0, standard 2.0, deep 4.0 s; *untuned*, measured in M10) is compared with the remaining moment **minus a 0.3 s margin**; this is the one statement of the skip rule the walk above uses. Nothing else runs inside the walk: a timed-out or cancelled backend is only **marked** `needs_reset` (its next `call` first awaits `reset()`, bounded by 0.5 s and by that call's own deadline; `finalize` closes every client), and the `CallRecord`s are collected and written **after** the walk returns (below), so neither spends the time left for the next tier.

Worked example on the PC Mouth under O1's `decide` route (`fast → standard → deep`): moment 6.0 s − output reserve 1.0 s = 5.0 s; `fast` times out at 2.0 s → 3.0 s left, minus 0.3 s margin = 2.7 s ≥ `MIN_TIER_S[standard]` 2.0 → `standard` runs with `fail_after(min(3.0, 3.0))`; if it returns `invalid` at, say, 1.5 s → 1.5 s − 0.3 s < 4.0 s → `deep` skipped, the walk ends, the default chain decides. A `fast` outage (`failed`, immediate) goes straight to `standard`. `test_brain_call` runs this walk on a real clock with fake backends that sleep. Each `b.call` runs inside `anyio.fail_after(min(PER_CALL_S[purpose][tier], deadline − now))`; on a timeout or cancellation the walk builds the `CallRecord` from the call's `CallAttempt` (D5: outcome `timeout` / `cancelled`, the sent payload, the reserved transmissions) for the audit write. A cancellation (the latch's scope) ends the walk at once; the collected records are written in the `finally` (below) and the cancellation is re-raised: `brain_call` maps nothing itself; `run_activity`, `negotiate` and the loop keep their M6 mapping to the latch's status. Provenance: *adapted* from FrugalGPT-style cascades (prior-art §2 #13), as ADR-0017 §5.1.

**Audit rows (T6, S4).** Every backend call of a walk gets one `brain_calls` row (D11), written by `audit.write(records)` once the walk ends, in `brain_call`'s `finally` (normal return, `None`, or cancellation): a shielded scope bounded by 0.3 s (not by the moment: the walk is over, and 0.3 s is inside the output reserve), one `busy.retry` inside it. The write is D22's `insert_named`; a row the fence refuses (a source learner is being forgotten) follows D22's one refusal rule (written with the payload re-rendered without that learner and `response` NULL), logged, never kept. A row the scope could not write because the store was busy is kept in `s.pending_audit` and written by the next successful write or by `finalize`, like M6's `pending_rows`. Test (`test_cancellation`): `stop` during the mediator's retry sleep → one `cancelled` row with `transmitted_attempts` 1, one unit charged, the boundary ends `stopped`; a busy store at that moment → the row written at `finalize`.

**D9 Tier and route settings [beyond ADR: key names, T17; amends ADR-0018].** Household `.env` keys, group Brain in `config/env-schema.json`: `BRAIN_TIER_FAST` (default `claude:claude-haiku-5-5`), `BRAIN_TIER_STANDARD` (`claude:claude-sonnet-5-5`), `BRAIN_TIER_DEEP` (`claude:claude-opus-5-5`), each a comma-separated `backend:model` list tried in order; empty = the tier is not configured. `BRAIN_ROUTES` (empty = ADR-0017 §5.1's table with O1's change, below) is a JSON override of single cells, validated at save. The habit track keeps `BRAIN_MODEL`. `BRAIN_DEADLINE_S` is removed (ADR-0017 §10). ADR-0018 §1/§5's single `BRAIN_TIERS` key is amended to these four keys in the M7a commit (O4). ### Sequencing, construction, the moment

**D11 `brain_calls` rows [beyond ADR in content, T6, T3].** Written only through D22's fenced writer (round 4 #2). One row per backend call: `payload` = the prepared JSON as transmitted (for a cloud backend: surrogates; for a local one: real text, as `LOCAL_MODELS` allows); `response` = the received text before `reverse`; payload provenance = `join` of the sent leaves; response provenance = D2's output rule; `estimated_cost` from a price table in `routing.py` (the vendor rows above; unknown model → NULL); `outcome` from the `CallRecord`.

**D12 Moments, filler, controls during waits [ADR §5.2, T7, T8].**
- `moment(s, name)` = `now + BUDGET[name][mouth] − OUTPUT_RESERVE[mouth]`, the session's primary Mouth kind (`pc`, `camera`; none → `pc`).
- **Controls during a Brain wait (T7, R5, S2, round 4 #1, #6):** every Brain wait runs inside `Inputs.controls_only(owner)`, and every activity listen is `listen(owner, …)`; both are defined once, with the readers, the stamps and the sentinels, in **D21**. The rest of this design refers to it and restates none of it.
- **Filler (T8).** `with_filler(s, epoch, coro)` runs `coro` and a filler child in its **own** `anyio` task group (not `latch.spawn`): the child sleeps 0.8 s, then, if the call has not returned and the epoch still equals `epoch`, shows "…" on Faces and on the PC Mouth says one filler phrase; on the camera Mouth Face text only (pushing a clip at the call's start needs the go2rtc path measured: M10, plan mode). When the call returns the child is cancelled and its cleanup awaited (`Hub.say`'s stop and the listening gate's resume) **before** `with_filler` returns, so nothing else speaks over it (one speaker at a time). A filler error is logged and never ends the session. While the filler line plays, `with_filler` sets `Inputs.speaking`, so a `skip` cuts the filler line only (as during any playback), and is not queued against the next activity (S12); outside the filler line a `skip` during a Brain wait goes to the skip queue as M6 defines (it belongs to the current negotiation). Provenance: *adapted* from Pipecat `pre_actions` (research R7), as ADR-0017 §5.
- **Epoch at output (T8).** Every Brain-derived line is spoken through `Talk.say(…, epoch=e)`, which drops the line when the live epoch differs from `e`; `apply_records` checks the live epoch, not only the observation's (ADR-0017 §1: an item built under one epoch is dropped when the epoch changed).
- **The epoch echo (T24).** The observation sends `turn` = an opaque per-session counter (`latch.epoch.turn_id`), never `session_id` or `learner_id`; a `Decision` whose `turn` differs from the observation's is dropped (`override = brain_unavailable`).

**D13 Sequencing and announcements [ADR §2.1, §3.3, T19].** `sequence` per the ADR under `with_filler` and the `next_activity` moment. `rationale_line(prop, a)` uses `rationale.strategy` only when `a` is the Brain's proposed `activity` (or its `alternative`, for which the Brain gave none, so the default chain's static line is used); never for a default-chain or other kind. `say_before` is spoken only at `autonomy ≥ bands.announce`, as the announcement of the Brain's `activity` when that is the activity `negotiate` returns; below that band it is not spoken.

**D14 Construction becomes async; content cached per boundary [ADR §3.3, T18, T11].** `construct`, `first_constructible` and `negotiate`'s callers become `async` in one commit (M7c), M6's tests ported with them. A `brain`-owned kind is constructed with **one** `generate` call per (boundary, kind, selection): the result is cached in `s.boundary.content[(kind, selection_key)]` with its epoch, so a re-offer, a silence re-ask or `first_constructible` walking past the same kind reuses it; a changed epoch clears the cache (`Reobserve`). All generation at a boundary shares that boundary's `next_activity` moment; when it is spent, `brain`-owned candidates are skipped (construction returns `Rejected("not available now")` without calling) and the default chain's `code`-owned steps remain. Content made for a refused offer has been charged; that is the price of a constructed offer (ADR-0017 §2.1 offers only constructed activities). Provenance: the cache *original*, keyed by the epoch *adapted* from fencing tokens as ADR-0017's epoch.

**Kinds gated until their handler exists (T11).** `menu.allowed` includes a kind only when `KINDS` has its handler; `quiz` (and any kind whose handler lands later) is absent from the menu, and therefore from the `decide` menu text, until M7c adds it. `decide`'s schema covers every kind from M7b on (one schema per session, byte-stable), and construction rejects a kind not in the menu.

### Generation, scoring

**D15 `generate` kinds and their checks [ADR §3.1; exact rules beyond ADR, T9, T20].** Purposes stay ADR-0017's: `decide`, `generate`, `answer`, `judge`, `word`. A learner's question in `learner_questions` is purpose **`answer`** (its own route and eligibility), never a `generate` kind. `generate` kinds: `teach_items` (per item `method`, `explanation` ≤ 300, `prompt` ≤ 150, `expect`), `quiz`, `read_aloud` (`translate`, `hard_sentence_ids` ≤ 3), `add_cards` (`front`, `back` ≤ 200, `sentence`), `notes` (D18), `book_note`.

**References are bound, not just existing (T9).** The observation renders ids, never bare keys: candidates as `m<miscue_id>`, items as `i<item_id>` with their key, sentences as `s<page_read_id>.<sentence_index>` of the open cycle's page reads at the current revision. A reference is valid only when it was rendered in **this** observation, belongs to this learner, and (for sentences) to a page read of the open cycle at its current revision; duplicates are dropped; a range `{from, to}` must name existing sentences of the current page read. An item cited by a question must have its key (after `norm`) in that question's text or answers or cited sentences. Provenance: reference binding *original*; answerability *adopted* from research N20 (ADR-0017 §3.1), with the every-set rule *original*.

**Quiz answerability (T9).** Per question: `evidence` non-empty, every cited sentence read in this cycle; `type` ∈ CROWD's five. For `completion`, `recall` and `wh-`: `answers` is a non-empty list of keyword sets, each non-empty, each with at least one non-function word (`WordInfo`), and **every** set must be supported: all its keywords occur, after `norm`, in the cited sentences; a question with any unsupported set is dropped. For `open-ended` and `distancing`: `answers` must be empty; the learner's answer is acknowledged, scored `unavailable` and writes no retrieval event or encounter (ADR-0017 §3.4's `unavailable`). A quiz left with no question is `Rejected`. This checks support, not the question's meaning: a question about the wrong character can pass (the measured check of D20 covers model behaviour).

**D16 Answer scores and `judge` [ADR §3.4].** `scoring.py` is pure: `item_said` and `cloze_word` use ADR-0013's pair classes through `WordInfo`; a spoken answer counts only when every word's confidence ≥ `ANSWER_MIN_CONF` (0.8); `item_used` is one `judge` call (`yes | no | cannot_tell`, few-shot examples fixed in `prompts.py`, five per class, invented sentences, no learner data; *adopted*, prior-art SS20/SS21). No eligible `judge` backend, a timeout or `cannot_tell` → `unavailable`.

### Items, records, evaluation

**D17 Item-status evidence and the fold [beyond ADR: a new table, T10, T21; research `2026-10-23-item-status-evidence.md`].** Migration 7 adds one append-only table:

```
item_status_events(id, learner_id → learners, item_id → knowledge_items, at, day,
  event CHECK IN ('ignore','unignore','card_ack','card_state','card_gone'),
  source CHECK IN ('brain','learner','owner','anki'),
  session_id → reading_sessions NULL, activity_id → activities NULL,
  card_id NULL, ivl_days REAL NULL, lapses INTEGER NULL, revlog_id INTEGER NULL, revlog_type INTEGER NULL)
```

`day` is the household date (`HOUSEHOLD_TZ`); `retrieval_events.day` is written the same way from M7d (it used `date.today()`). Writers: `apply_records` (`ignore` from the Brain), the learner's request (`ignore`, source `learner`: a new control phrase "I know this word" in `controls.parse`, accepted only inside `teach_items` / `recall_items` for the current item; *original*), `unignore` from the owner's `python -m leafi items unignore --learner N --item ID` (and `items ignore`; the Brain may only request `ignore`); `anki.sync_outbox` on the first acknowledgement of an item's card (`card_ack`, with `card_id`, **`session_id` NULL**: it records that the card exists, not session evidence); and `card_state` whenever Leafi observes the card:
- after an acknowledged answer: the revlog row whose `id` ≥ the answer's `sent_at` (`getReviewsOfCards`, already called by `reconcile`) gives `ivl` and `type`, `cardsInfo` gives `lapses`; `ivl_days` = `ivl` when `ivl ≥ 0`, else `−ivl / 86400` (a negative `ivl` is a duration in seconds, R7);
- **`anki.observe_cards(store, client, learner)`**, run once at the first boundary of each session when Anki is reachable: `cardsInfo` over **every** card id of the learner's acknowledged outbox rows (batches of 100), not only due ones, writing a `card_state` (session NULL) when `interval` or `lapses` differs from the latest stored state **of that card id**, or when that card id's latest event is `card_gone` and `cardsInfo` returns it again (a card restored in Anki, round 4 #7), so a review done in Anki itself that made a card non-due is seen at the next session (R7). `card_gone` is written only when `cardsInfo` answers and the id is **absent: missing from the reply, or present as an empty entry (`{}`, no `cardId`)**, never on `AnkiUnavailable` or `AnkiError` (round 5 #14: AnkiConnect may return `{}` for an unknown id; `observe_cards` and `due_cards` both read entries with `.get`, never `c["cardId"]`; `test_anki` covers an omitted and an empty entry). `sync_outbox` writes `card_ack` per (item, card id) that has no live membership yet (no event, or its latest is `card_gone`), not only on the item's first acknowledgement.

`anki._update_status` is deleted; it compared the interval from **before** the answer. **Migration 7 backfill (R7):** one `card_ack` (at = the row's `updated_at`, source `anki`, session NULL) per acknowledged `anki_outbox` row with card ids; the first `observe_cards` then records their states; until it runs, those items fold to `learning` (the card exists, its state is unknown), never `known`.

`item_status.fold(retrievals, events, mode) -> (status, next_recall_day)` is pure and **total** (R6): every input, including the empty one, has exactly one result, decided by the first rule that applies:
1. **Ignored.** The latest of the item's `ignore`/`unignore` events is an `ignore` → `ignored` (no recall day). An `unignore` only removes this rule; the rules below then decide from the rest.
2. **Follows a card.** The item has a card when any surviving `card_ack` **or** `card_state` names a card id with no later `card_gone` for that card id (membership survives a forgotten session because all three are written session-less, above). `card_gone` (a fourth `event` value, S8) is written by `observe_cards` when a tracked card id is absent from `cardsInfo` (the card was deleted in Anki); a card that reappears gets a new `card_ack` at its next acknowledgement. With every card gone, rules 3–5 decide. With a card, in **both** mastery modes (ADR-0017 §6.2): the item's **live card** is the live card id with the latest event (an item normally has one); no `card_state` of it yet → `learning`; else from its latest state: `ivl_days ≥ REVIEW_KNOWN_INTERVAL_DAYS` → `known`; an earlier state **of the same card id** at or above the threshold and `lapses` greater now than at that state → `lapsed`; else `learning` (lapses are never compared across card ids, round 4 #7). No recall day (Anki schedules).
3. **No evidence.** No surviving retrieval event → `new` (in both modes; this is the result after `unignore` of a never-practised item and after `forget --session` of its only session).
4. **Retrievals, no card.** At least one retrieval event: `mastery.mode = anki` → `learning` (the card is the path to `known`). `mastery.mode = retrievals`: walk the events in `(at, id)` order from `learning`: `known` once ≥ `mastery.min_retrievals` successes over ≥ `mastery.min_days` distinct household days have been counted since the last reset; in `known`, a `fail` → `lapsed` and the count resets; in `lapsed`, the same threshold, counted from the lapse, returns it to `known` (*original, untuned*: ADR-0017 leaves `lapsed` undefined in this mode).
5. **`next_recall_day`**, only for rule 4's `learning` and `lapsed` items: 1 day after the first event; each success moves the step along 1 → 2 → 4 days from that success's day; a `fail` resets it to 1 day after the fail; `unavailable` writes no event, so changes nothing.

Hand-run (`retrievals` mode, threshold 21 days), events in order (S5):
1. session S1: one `success` retrieval → rule 4 → `learning`, next recall S1's day + 1;
2. `ignore` → rule 1 → `ignored`;
3. `unignore` → rules 2–4: no card, S1's retrieval survives → rule 4 → `learning`;
4. `card_ack` → rule 2, no state yet → `learning` (no recall day: Anki schedules);
5. `card_state` with `ivl_days` 25 → rule 2 → `known`;
6. `forget --session S1` → S1's retrieval deleted; the card events (session-less) survive → rule 2 → still `known`;
7. `card_gone` → no card left, no retrieval left → rule 3 → `new`.
Without steps 4–5, step 6 leaves no evidence → rule 3 → `new`. An item never practised, ignored then unignored → rule 3 → `new`. In both modes an item with a card follows its card (ADR-0017 §6.2: "In both modes an item with an acknowledged Anki card follows Anki's state"). Provenance: status as a fold over an append-only log *adapted* from Anki's `revlog` (research note, finding 4).

`item_status.apply(store, item_id)` = run the fold and write `knowledge_items.status` (now a cache) in the caller's transaction; it is the only status writer. **Forget (T10):** `forget --session` collects the affected item ids before deleting that session's `retrieval_events` (by `activity_id` of its activities) and its session-bound `item_status_events` (`ignore`/`unignore` with that `session_id`), then calls `apply` for each affected item in the same transaction, so an item with no surviving evidence returns to `new`; `forget --learner` deletes the learner's items with their events and calls nothing (the deletion order is D22's). Every `card_ack` and `card_state` is written with `session_id` NULL (also the one read after an answer inside `review_anki`; its `activity_id` is kept for the record and set NULL by `_delete_session_records` before it deletes that session's activities, D22), so `forget --session` never removes card evidence: it describes a card that still exists, and the card goes only with `forget --learner` (and `--delete-anki-deck`), which deletes the learner's events. Tests: `test_item_status` (each rule, empty history, ignore then unignore, card in `retrievals` mode), `test_mastery`, `test_recall_schedule`, `test_forget` (a known item loses its qualifying session → `learning`; all evidence gone → `new`).

**Ranking (O5, O6).** One-unknown sentences first, where **known** = this learner's items in `known` or `ignored`, or a function word (`WordInfo`); `learning`, `lapsed` and `new` count as unknown, as the card checker already does (O6). Then the level band from CYP-LEX alone: ADR-0017 §6.2's YLE-first rule is deferred explicitly with the YLE parser (O5, Decision log). Then frequency. One function `items.is_known(learner, lemma)` serves ranking and the card checks.

**D18 Records and notes [ADR §7.1].** `apply_records` validates `assessment` (≤ 500), `item_status` (only `→ ignored`, written as an `ignore` event), `book_note`, each separately; one transaction; the live epoch checked (D12); provenance by D2. `extract_notes`: one `generate` call (`notes`: ≤ 5 notes, each ≤ 200 chars, each citing ≥ 1 activity id rendered in the post-session observation of this session), under `post_session_context` (D7's call-counted budget), the same filter (D3) for a learner whose `cloud.text` is off (or an eligible local backend), skipped for guests; a note citing an unrendered id is dropped. A note whose cited activities are all more than 10 sessions old, with no newer citing note, leaves `memory` (observation query); `forget --session` deletes a note whose citations all point into that session (both existing ADR rules, given steps and tests here, T22). **Interests (A3, owner 2026-10-24) are M7f's** (migration 8: `learner_notes.kind` = `note` | `interest`; a parent writes `parent`-class interests, the Brain `derived_from_learner` ones through `extract_notes` and a new `decide` record kind `interest`); this design leaves room for them: D6's two-level validation drops an invalid `interest` record alone, D3's `memory` section renders interests as leaves of their own class (a parent interest with `CLOUD_PARENT_TEXT` off is withheld), and D22 needs nothing new (`learner_notes` is already `DIRECT` and `PROVENANCE`).

**D19 Arms and the replay set [ADR §9; file shape beyond ADR; O2, T4].** `python -m leafi report arms` prints per arm: sessions, propensity, the per-session outcome of §9 with its IPW mean, override counts, and, always, the line "a smoke check: no conclusion without a stated effect size and sample size (ADR-0017 §9)" (T24).

The replay set (O2: **on by default**, setting `EVAL_DECISIONS` = `on` | `off`, household, in `PRIVACY_FLOOR`). **Stored in `data/leafi.db`, not in JSONL files** (R8): a file rewritten by `forget --learner` races a running session's append (a line built before the rewrite, holding the forgotten learner's note, is appended after it), and only the database already has the fences that close that race. decision_records(id, learner_id → learners, session_id → reading_sessions, at, turn,
  record TEXT NOT NULL,                       -- JSON: leaves {section, value, provenance: {cls, sources}},
                                              --   the menu, the decision, the executed activity, the outcome

### The two rules every round came back to (rev 5, round 4)

Four rounds found instances of two decisions (input ownership: T7 → R5 → S2 → round 4 #1, #6; derived writes outside the fence: T4 → R8 → S7 → round 4 #2, #3). Each is now one executable statement; every other decision refers to it, and a test suite hand-runs it on named inputs.

**D21 Input ownership (one statement) [beyond ADR, *original*].** The rule: **an input belongs to the prompt that was current when the learner finished it; a prompt is current from the moment Leafi starts presenting it** (the first word of its line, or its Face text when nothing is spoken), not from the moment Leafi starts listening (round 5 #1). A spoken utterance is finished when its last speech chunk was captured; a typed line when the console read it from the keyboard (round 5 #3). Who requested the read, and when the item reached the stream, do not matter.

```
clock      = time.monotonic, one clock for Inputs, the Listeners and the console (injected in tests; it is
             already the clock of AudioChunk.t, VoiceListener and asyncio's loop.time())
Owner      = (prompt_id, epoch)
prompt_id  = ("act", activity_id, step)      every spoken question of an activity has its own step
           | ("page", page_read_id)           read_listen: one prompt for the whole page read
           | ("offer", turn, n)               each offer or question of negotiate (§2.1)
           | ("wait", turn)                   a Brain wait at a boundary
             a follow-up within the same item reuses its parent's prompt_id
Item       = Utterance(u, owner) | Skip(owner) | Page(owner) | Timeout(owner) | Switched(epoch)
u.ended_at = voice: the `t` of the segment's last speech chunk (AudioChunk.t), set by the Listener before
             `_recognise`; typed: the console thread's clock() at `readline` (ConsoleDevice queues (line, t)
             and `typed_utterance(text, t)` carries it); never the time the item is popped

Inputs state:
  owners:   list[(since, Owner)]  # timeline; pruning drops entries older than 60 s EXCEPT the newest entry at or
                                  # before the cutoff, so owner_at(t) is defined for every t after the first
                                  # present() (round 5 #6)
  inflight: dict[source, bool]    # at most one read per source, as today (`_busy`)
  stream:   the existing `_send/_recv` memory stream of Items

present(o): if owners.last != o: owners.append((clock(), o))
  # called by say(…, owner=o) BEFORE its line plays, by Face-only prompts when shown, and by listen() and
  # controls_only() on entry (a no-op when o is already current)
owner_at(t) = the Owner of the last entry with since <= t

request(src): if not inflight[src]: inflight[src] = True; start a read on src, remembering t_req = clock()

reader(src): loop: wait for a request; u = await src.next_utterance(None); inflight[src] = False
  if u is None:           send(Timeout(owner_at(t_req)))                 # the asker's silence, nobody else's
  elif control(u) is stop: terminate("stop")                              # controls act at once
  elif control(u) is skip:
      if speaking: cut the current line                                   # as today (incl. the filler, D12)
      else: post_skip(); send(Skip(owner_at(u.ended_at)))                 # round 5 #2: wakes the listener
  elif control(u) is page: send(Page(owner_at(u.ended_at)))               # "/page", "next page"
  else:                    send(Utterance(u, owner_at(u.ended_at)))
page_watcher: only while page_open: on a settled turn: send(Page(owner_at(clock())))
ear_lost:     E = bump epoch; send(Switched(E))

ACCEPTS_PAGE = {read_listen, practise_errors}        # per kind (round 5 #4); M7f adds its listening steps

listen(o, timeout_s, kind):
  present(o); deadline = clock() + timeout_s
  loop:
    for src in wanted_sources(): request(src)   # every iteration: a source freed by a stale read is asked again
    item = await stream.receive() until deadline, else return None
    if item is Switched: if o.epoch < item.epoch: raise StaleInput
                         else: continue          # already handled: the caller was built after the switch (round 5 #5)
    if item.owner != o: log("stale", item); continue
    if item is Timeout: return None
    if item is Skip: take_skip(); return SKIP    # consumes the queued skip once
    if item is Page: if kind in ACCEPTS_PAGE: return PAGE
                     else: log("page ignored"); continue
    return item.u

controls_only(o):                                # around every Brain wait
  present(o)
  in its own task group: loop: for src in wanted_sources(): request(src); await a delivery or exit
  on exit: nothing is consumed; items stay in the stream, stamped, for the next listen() to filter

boundary pages: a Page owned by a ("wait", turn) or ("offer", turn, n) prompt (typed during a Brain wait or an
  offer) is consumed by the boundary: it sets the pending page request and returns Reobserve (§2.1), so the
  next activity is chosen for the new page instead of being cut by it

wanted_sources() = {control source} ∪ ({main} if text mode or (voice mode and no Mouth playing))   # ADR-0011
```

Consequences, each a test through the real `Inputs` with scripted console and voice sources (`test_inputs_ownership`):
1. **Late voice across items.** The learner speaks during A's `judge` (last chunk at t1, owner A); the transcription lands while B is listening → owner A ≠ B → dropped; B's `request` runs again on the next iteration, so B's own answer is read (no hang).
2. **Busy reader.** A's console read is in flight when B's question starts; the learner types B's answer after that → `ended_at` after B's `present` → owner B → returned to B.
3. **Answer typed during the question (round 5 #1).** B's question is still playing when the learner types → `present(B)` ran before the line → owner B → returned to B's listen (today's behaviour kept).
4. **Line typed before B's question started (round 5 #3).** The console thread stamped it at `readline`, before `present(B)` → owner A → dropped; it is not given to B even if no read was in flight.
5. **Follow-up.** A's "tell me more" listens with A's prompt id → A's late addition is returned to it.
6. **Stop** typed or spoken (outside a playing line, where the gate pauses the voice Listener) during a Brain wait → `terminate("stop")` inside `reader`, whoever the owner is.
7. **Skip (round 5 #2).** "skip" during a `read_listen` listen, text or voice → a `Skip` owned by the page prompt wakes the listen, which returns `SKIP` after consuming the queued skip once; a skip during a Brain wait at a boundary is owned by the wait, dropped by the next activity's listen, and stays in the queue for `negotiate`'s `take_skip` (M6's rule: it belongs to the current negotiation).
8. **Ear lost during a wait (round 5 #5)** → `Switched(E)`; the boundary re-observes under E; the next activity's listen (epoch E) drops the item instead of raising; a listen built before the switch (epoch < E) raises `StaleInput` as today.
9. **Page typed during `decide` (round 5 #4)** → owned by the wait prompt → consumed by the boundary (pending page, `Reobserve`), not by the `practise_errors` that follows; a page turn during `practise_errors` ends it `page_turned` as today.
10. **Long listen (round 5 #6):** a 5-minute text-mode `practise_errors` listen still owns its input after the 60 s pruning.
11. **Two answers for one prompt** → both returned, in order.

The listening gate (ADR-0011) still pauses the voice Listener while a Mouth plays; `wanted_sources` only decides which reads are requested, so during a playing line only the console is read.

**D22 The fenced writer (one statement) [beyond ADR in coverage; the fence *adopted* from M3's `learner_store.insert`].** The rule: **no row that names a learner — as owner or in any `*_source_learners` column — is written unless, in the same SQL statement, every named learner exists with `forgetting = 0`.** With `forget --learner`'s order (mark in one transaction, then delete, then rescan), this makes "after the rescan no row names the learner" true for every writer, in every session.

```
named(owner, cols) = ({owner} if owner else ∅) ∪ stated_sources(cols) − {PARENT_SOURCE}
fence(ids)  = "(SELECT COUNT(*) FROM learners WHERE id IN (ids) AND forgetting = 0) = len(ids)"

learner_store.insert(table, owner, **cols):           # existing; DIRECT tables
  INSERT INTO table(cols) SELECT values WHERE fence(named(owner, cols))
learner_store.insert_named(table, **cols):            # NEW: tables with provenance columns but no learner_id
  INSERT INTO table(cols) SELECT values WHERE fence(named(None, cols))       # brain_calls
learner_store.update_named(table, row_id, **cols):    # NEW: an UPDATE that sets provenance columns
  UPDATE table SET cols WHERE id = row_id AND fence(named(row_owner(table, row_id), cols))
    # row_owner: the row's own learner (activities → its session's learner), so the owner is fenced too
every call: rowcount != 1 → raise LearnerUnavailable

forget --learner A (existing order, unchanged):
  T1: mark A forgetting                                # from here every fenced write naming A fails
  T2…: delete A's sessions, items, events, rows        # in the order below
  Tn: _purge_derived(A)                                # final rescan over learner_store.PROVENANCE
```

**Coverage.** `learner_store.PROVENANCE` and `DIRECT` are the registry; M7 adds `brain_calls` (via `insert_named`), `decision_records` and `item_status_events` (`DIRECT`), and routes every provenance-setting UPDATE through `update_named`: `rows.finish_activity`'s `outcome_*` columns and `apply_records`' `assessment_*` columns. Two existing writers move onto `learner_store` in M7a: `activities._store_utterance` (`utterances` names a learner in `source_learners` and is written today through the generic `Store.insert`, unfenced) via `insert_named`, and `identify.adopt`'s `UPDATE reading_sessions SET learner_id` (fenced by hand today) via a new `learner_store.reassign(table, row_id, learner)` (round 5 #7).

**`tests/test_architecture.py` gains the enforcement (round 5 #7),** scanning every `.py` under `leafi/` outside `leafi/core/learner_store.py` and `leafi/core/storage.py`:
- (a) **every INSERT** into a table of `DIRECT` or `PROVENANCE` is a violation, in any of its three forms: a literal `INSERT INTO <table>`, a call `store.insert("<table>", …)` / `Store.insert` with that table name, and a dynamic `INSERT INTO {…}` (flagged unless the function is on the exemption list);
- (b) **an UPDATE is a violation only when its SET names** `learner_id`, a `*_source_learners` or a `*_provenance_class` column; UPDATEs of status, timestamps, counts, Anki ids and the like (≈ 20 today: `loop.py`, `rows.py`, `activities.py`, `world.py`, `anki.py`, `knowledge.py`, `records.py`, `guests.py`) do not name a new learner and stay as they are;
- the **exemption list** names functions, not files: `records._delete_session_records`, `records.forget_learner`, `records._purge_derived` (they delete, or clear provenance to `system` / `[]`, and never name a learner), `guests.discard`, `migrate`'s `rebuild()`; each entry says why;
- the test lists today's offenders as its first red run (`_store_utterance`, `rows.start_activity` via `store.insert("activities", …)`, `adopt`), and M7a's commit moves them, so the rule is green from M7a on. Hand-run, `test_forget_race`: B's session builds a `brain_calls` row and an assessment quoting A; `forget --learner A` marks A; the session then writes both → both refused (`LearnerUnavailable`); by the rule below the audit row is written again with its payload re-rendered without A and `response` NULL, and the assessment is dropped, **neither kept in `pending_audit`**; after the rescan no row holds text derived from A under another learner's name; the activity still finishes (its `outcome` written without A's leaves: `finish_activity` recomputes the outcome provenance from what it stores); after the rescan no row names A.

**Who catches `LearnerUnavailable` — one rule (round 5 #9).** The session's own learner B cannot be marked while B's session runs (`forget_learner`'s `post_done_at` guard), so a refusal always means **another** learner named in the row's sources is being forgotten. Every fenced writer then does the same thing, and it distinguishes two kinds of stored text (round 6 #7):
- **Raw leaves** (text Leafi itself rendered from stored data, each leaf with its own provenance: the prepared payload of a `brain_calls` row, the leaf list of a `decision_records` row) can be **re-rendered without A**: every leaf whose sources name A is dropped or replaced by D3's substitute (a heard word becomes expected word + category; a note becomes nothing), and the provenance is recomputed from the leaves that remain, which is exact because each remaining leaf carries its own sources.
- **A Brain output** (`brain_calls.response`, an `assessment`, a decision's `say_before` / `rationale` / content fields, an explanation, a card back, a note, an interest) is **atomic**: by D2 its sources include every learner whose text the backend saw, it cannot be split back into leaves, and recomputing its provenance after "removing A" would store text derived from A labelled as B's alone, which `_purge_derived` would then miss. **A Brain output whose provenance names A is therefore dropped, never relabelled.**

So the one rule is: **retry once with A's raw leaves re-rendered and every Brain output naming A dropped; drop the whole row if nothing meaningful is left**, logging either outcome:
- an audit row: written with the re-rendered payload, `response` NULL, `outcome` kept (the call happened and was charged); a `decision_records` row: **dropped outright** (its value is the observation together with the decision; without the decision it is not a replay record); an assessment: dropped (it is only a Brain output);
- a step effect of B that quoted A (an encounter explanation built from a note of A, an `add_cards` card whose back cites it, a learner note or interest of B citing an activity that showed A's note): the explanation / card text / note is regenerated without A's leaves only if it can be rebuilt from stored data (`code` content); a Brain-written text is not regenerated mid-step, so the encounter is written with `explanation` NULL, the card is not queued (logged; `add_cards` reports it as `reject`), the note is dropped;
- `learner_store.retry_without(table, cols, foreign)` implements the removal once, for every writer.
`test_forget_race` covers each kind: `brain_calls`, an assessment, a decision record, an encounter, an outbox card, a note. `anki.sync_outbox` and `anki.reconcile` (which process every learner's rows, round 4 #3) skip learners with `forgetting = 1` in their query and catch `LearnerUnavailable` per row. **The orphaned note (round 5 #10):** when `sync_outbox`'s acknowledgement UPDATE matches 0 rows (the outbox row was deleted while `addNote` was awaited) or the row's learner is `forgetting`, the note id returned by Anki is recorded on the marked learner row (`records._remember_notes`, the existing list `forget` reports and `--delete-anki-deck` removes), so a card holding A's words is never lost from the deletion list.

**Deletion order with foreign keys on (round 4 #3).** Inside `_delete_session_records(session)` (so both `forget --session` and `forget --learner`'s per-session loop run it): `UPDATE item_status_events SET activity_id = NULL WHERE activity_id IN (session's activities)`, then `DELETE FROM item_status_events WHERE session_id = ?` (the session-bound `ignore`/`unignore`), then `DELETE FROM decision_records WHERE session_id = ?`, before its existing `DELETE FROM activities`. In `forget_learner`'s items block: `DELETE FROM item_status_events WHERE learner_id = ?` and `DELETE FROM decision_records WHERE learner_id = ?` before `DELETE FROM knowledge_items`. `forget --session` then calls `item_status.apply` for the affected items that still exist (round 4 #12: `forget --learner` deletes the learner's items, so it calls nothing). **`guests.discard` (round 5 #8)** deletes a guest's `item_status_events` and `decision_records` (by `learner_id`) before its `knowledge_items`, in the same transaction; `test_guests` discards a guest that wrote an `ignore` and a `card_ack` with foreign keys on.
